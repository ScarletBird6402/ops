## 0. 선행 작업 — GitHub 재연동 체크리스트 (Windows)

1. `git config --global user.name / user.email` — 공개 커밋용 계정 정보(개인 식별 최소화 확인)
2. 자격 증명: Git Credential Manager 또는 SSH 키 재등록 (기존 키는 구 환경 폐기분이면 GitHub에서 revoke)
3. `swe-notes` · `swe-projects` 2종 clone → 각 레포에서 `git log -1`로 최신 커밋이 정합화 완료 시점(H4 제거 커밋)인지 확인
4. `gen_index.py` 동작 확인: 마스터플랜 v3를 로컬 작업 폴더에 두고 실행 → "카테고리 26 / 항목 209 / 링크 18" 재현되면 환경 OK
5. `.gitignore` 확인: gen_index.py·repo_fix.sh·마스터플랜이 공개 레포에 안 들어가는지
6. (권장) 작업 루트 구조를 §3 레이아웃으로 미리 배치 — 에이전트 도입 시 그대로 사용

## 1. 목표와 단계

**최종 목표**: "보고 접수 → 트리아지 → 생성 → 검증 → 게시(커밋+index)" 루프의 기계화.
**도입 원칙**: 판단(트리아지·검수 승인)은 사람+마스터가 유지, 기계는 **검증과 반복 작업**부터.

| 단계 | 내용 | 성공 기준 |
|---|---|---|
| **A. 검증 훅** (1순위) | 정본 무결성 + 산출물 린트 + 민감어 스캔의 자동 실행 | §4의 검증 항목이 커밋/발행 전 강제됨 |
| **B. 게시 자동화** | 게시 확정 → PUB 갱신 → index 재생성 → 커밋 | 게시 1건당 수작업 0 |
| **C. 생성 파이프라인** | 큐(계획표) → 생성 프롬프트 조립 → 생성 → A 검증 → 검수 대기함 | 프롬프트 팩 수동 조립 소멸 |
| **D. 트리아지 보조** | [신규 후보] 접수 시 정본·접촉로그 자동 대조 리포트 | 중복 후보 사전 검출 |

## 4. 검증 스펙 (단계 A의 본체 — 전부 실측 사례 보유)

### 4-1. 정본 무결성 (canon 변경 시)
- [ ] 코드 중복 0 / 컬럼 수 8 고정 / 난이도 ∈ {L1,L2,L3} / 분량 ∈ {S,M,L}
- [ ] 선수·cross의 댕글링 참조 0 — `(cross: …)` 표준 표기 + **비표준 괄호·각주까지** 스캔
- [ ] 카테고리 헤더 ↔ 골격 테이블 정합, 항목 총계 리포트

### 4-2. 산출물 린트 (학습자료 HTML 커밋 전)
- [ ] 파일명 = `코드 제목.html` (정본 제목 대조, **괄호 병기부 제거 규칙**)
- [ ] 폴더명 = `코드 카테고리명` (정본 카테고리 대조 — 가운뎃점 누락류 검출)
- [ ] href 전수: 확정 코드·제목만 / 코드 접두어 ↔ 폴더 문자 일치
- [ ] 골격 섹션 순서 · 태그 균형 · **전달 단계 파일명 오타 대조** (Sonnet·C11 사례)

### 4-3. 경계 스캔
- [ ] 반입 세트(브리프+플랜): 민감어 패턴 0건 → 결과를 브리프 상단 부기
- [ ] 공개 리포: 민감어 + 내부 용어(사내·본부·브리프·반입) 0건

### 4-4. 게시 파이프라인 (단계 B)
- [ ] PUB 갱신 → gen_index.py 재생성 → 4-2 린트 → 404·고아 링크 0 확인 → 커밋
- [ ] CURRICULUM ✅ 마크 = PUB 집합 일치

### 4-5. 트리아지 보조 (단계 D)
- [ ] [신규 후보] 키워드를 정본 전 항목과 유사도 대조 → 인접·중복 후보 리포트
- [ ] 사내 보고 코드: 실존 검사 + 매핑표(F→I, G→J, H→K, K→O, B→?) 역추적 힌트
- [ ] 접촉 로그 자동 집계: 재접촉 카운트 · 주간 신규율(Phase 2 판정 지표)
