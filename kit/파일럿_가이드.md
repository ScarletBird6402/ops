# Claude Code 파일럿 가이드 — swe-notes 생성 파이프라인

> 목표: 에이전트 2개(생성·검증)로 학습자료 2~3건을 돌려 **품질·사용량을 체감**하고 확장/축소를 판단.
> 전제: Max 플랜(확인됨). 방(Q&A·트리아지)은 그대로 유지 — 이건 전환이 아니라 **파이프라인 층 추가**.

## 1. 설치 (최초 1회)
1. Claude Code 설치: https://code.claude.com/docs 의 설치 안내(Windows 지원). 설치 후 터미널에서 `claude` 실행 → **구독 계정으로 로그인**.
2. ⚠ 환경변수 `ANTHROPIC_API_KEY`가 설정돼 있으면 구독이 아니라 API 종량 과금으로 붙는다 — PowerShell에서 `$env:ANTHROPIC_API_KEY` 쳐서 비어 있는지 확인.

## 2. 킷 배치 — 부모 폴더 구조 (권장)

작업 루트 폴더를 만들고 두 레포를 그 아래에 클론한다:
```
claude-work/                  ← Claude Code 실행 위치 (git 저장소 아님)
├─ CLAUDE.md                  ← 킷의 CLAUDE.md
├─ .claude/agents/학습자료-생성.md
├─ .claude/agents/게시-검증.md
├─ ops/                       ← 운영 레포 클론 (GitHub에서 Private으로 생성)
│   ├─ plans/  briefs/  logs/  kit/   ← 초기 폴더 (kit/에 이 킷 백업 커밋)
└─ swe-notes/                 ← 산출물 레포 클론 (공개)
```

**이 구조의 보안 이점**: `CLAUDE.md`·`.claude/`가 어느 레포에도 속하지 않아 **커밋될 경로 자체가 없음** — 이전 안(.git/info/exclude)이 불필요해짐(구조적 차단 > 습관 의존). 다른 PC 셋업 시엔 ops/kit/의 백업으로 복원.

- ops 레포 생성 시 **Private** 선택을 반드시 확인(운영방침 §0: 영구 비공개, 공개 전환 금지).
- 첫 실행: `claude-work/`에서 `claude` 실행 → 폴더 신뢰(trust) 승인.

## 3. 파일럿 실행 (자료 1건 사이클)
`claude-work/`(부모 폴더)에서 `claude` 실행 후:
```
[마스터 방에서 정한 항목 붙여넣기 — 예시]
J11 항목을 생성해줘.
- 코드: J11 / 카테고리: J 테스트·품질
- 주제: 테스트 결정성과 환경 의존 함정
- 키워드: flaky test·타임존/로케일/시스템 시각 의존·고정 시간대·결정적 테스트
```
→ 생성 완료 후:
```
게시-검증 에이전트로 방금 만든 파일 검사해줘.
```
→ PASS면:
```
커밋해줘. index.html 최근 추가도 갱신해서 같은 커밋에.
```
→ push는 SourceTree(또는 `git push`)로 직접. (에이전트에 push 권한을 주지 않는 게 안전)

## 4. 판단 기준 (2~3건 후)
| 관찰 | 판단 |
|---|---|
| 품질이 방에서 만들던 것과 동등 이상 | 파이프라인 유지 |
| `/usage`로 확인한 소모가 부담 없음 | 나머지 도메인 확장 or 범용 생성기 그대로 사용 |
| 소모가 큼 | 생성은 방에서, **검증·커밋만 Code로** 축소 (검증은 저렴) |
| 품질 미달 | 에이전트 프롬프트 보정 후 재시도, 그래도 미달이면 방 유지 |

- 사용량 확인: Code 안에서 `/usage` (플랜 사용량 막대). 파일럿 결과가 곧 **Pro 전환 판단 데이터**가 된다 — 자료 1건당 소모율을 기록해두면 "월 N건 생성 시 Pro로 충분한가"를 계산할 수 있다.
- 모델 조정: 두 에이전트 모두 frontmatter `model: sonnet`. 검증은 `haiku`로 낮춰도 무방(더 저렴). 생성 품질을 올리고 싶으면 생성만 상위 모델로.

## 5. 도메인 특화가 필요해지면
현재 생성 에이전트는 **범용**(생성 규칙이 도메인 무관이므로). 마스터 방 논의 결과 도메인별 관점 차이가 필요하면, 파일을 복제해 이름·description에 도메인을 박고 본문에 "이 도메인에서 특히 강조할 관점" 섹션만 추가하면 된다.

## 6. 역할 경계 (혼동 방지)
- **Code(이 파이프라인)**: 생성 → 검증 → 커밋 → index 갱신 (기계적 반복)
- **방(유지)**: 도메인 Q&A·학습 대화, 마스터 방의 트리아지·코드 배정·사내 브리프 (판단)
- 신규 토픽 발굴은 여전히 방/사내 보고 → 마스터 방 배정 → 확정 코드로 이 파이프라인에 투입

## 7. (선택) 모바일·웹에서 세션 보기 — Remote Control
- 세션 안에서 `/remote-control` 실행 → 같은 세션이 **claude.ai/code 와 Claude 모바일 앱**에 나타남. 대화가 모든 기기에서 동기화되고, 터미널·브라우저·폰 어디서든 이어서 지시 가능. 긴 작업 완료·승인 필요 시 폰 푸시 알림.
- 제약(연구 프리뷰): 실행은 여전히 로컬 PC — **터미널을 닫으면 세션 종료**, 오프라인 ~10분이면 타임아웃, 원격에서도 액션 승인 필요(안전상 장점이기도 함).
- 활용 패턴: 생성 배치를 걸어두고 외출 → 폰에서 진행 확인·검증 결과 보고 커밋 승인.
- 주의: "Claude Code on the web"(클라우드 실행)과 다름 — 클라우드 방식은 `.claude/`가 레포에 커밋돼 있어야 해서 우리 보안 설계(exclude)와 충돌. **로컬 실행 + Remote Control만 사용할 것.**
