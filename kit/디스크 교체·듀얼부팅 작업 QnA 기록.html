01

하드웨어 교체

물리 작업에서 나온 질문들.

3.5" 케이지의 HDD가 당겨도 안 나온다
순서 문제였다: ① SATA 데이터·전원 케이블 먼저 분리 ② 경로를 막는 케이블 타이 절단 ③ 양쪽 클립을 쥔 채로 유지하며 수평으로 당기기. 걸리면 힘이 아니라 걸림 지점을 찾을 것 — 특히 데이터가 든 디스크는 절대 비틀지 않는다.
트레이에서 디스크가 분리되지 않는다 (나사는 다 풀었는데)
툴리스 트레이는 나사가 아니라 옆 레일의 핀이 디스크 옆면 나사 구멍에 끼워지는 구조. 레일 가운데를 바깥으로 낭창하게 벌려 핀을 구멍에서 빼내고, 그쪽 모서리를 비스듬히 들어 올리면 분리된다. 힘은 플라스틱 레일에만, 기판 쪽은 지렛대 금지. 새 디스크 장착은 역순.
메인보드 뒷면 I/O의 "BIOS FLBK" 버튼과 흰 테두리 USB 포트의 정체는?
BIOS FlashBack — CPU·부팅 없이 USB 메모리로 BIOS를 강제 재기록하는 복구 기능. 평시에는 절대 길게 누르지 말 것(USB가 꽂혀 있으면 플래싱 시작). 역으로, 키보드조차 안 듣는 최악 상황에서 BIOS를 업데이트할 수 있는 최후 수단이기도 하다.
기존 X300 4TB는 어떻게 처리하나
Phase 9까지 대기 상태: 구 시스템 데이터의 마지막 안전망이므로 새 시스템 1~2주 실사용 확인 전에는 포맷하지 않는다. 정전기 방지봉투에 평평하게 보관. 편입 시 SMART(05/C5/C6 = 0) 확인 후 아카이브 전담으로 전환 예정.
02

BIOS · 부팅 체인

이번 작업 최대 난관(키보드 먹통)과 부팅 관련 전부.

Secure Boot에 Disabled가 없고 Standard/Custom뿐이다
ASUS 계열은 키 관리로 끄는 구조: Custom 선택 → 키 관리 → PK 삭제, 또는 더 간단히 OS 종류 → 기타 OS. 판정 기준은 Mode 표시가 아니라 "안전 부팅 상태 = Setup"(켜짐이면 User). 키를 지워도 Mode가 Custom인 것은 정상이며, "Restore Default Keys"로 언제든 원복 가능.
BIOS 설정 화면에서 손댈 것과 두는 것
전압·코어 비율·메모리 주파수 = 전부 자동(기본값) 유지. 확인만 할 것: CSM Disabled, TPM(Firmware TPM) Enabled 유지. DDR5가 4800MHz로 뜨는 것은 JEDEC 기본 속도로 정상이며, XMP는 시스템 안정화 후 필요 시 — 설치 중 변수를 줄이는 것이 우선.
GRUB·BIOS에서 키보드·마우스가 전멸했다 (OS에선 정상)
이번 작업 최대 이슈. 진단 사슬: OS에서 되고 펌웨어 단계만 죽음 → 하드웨어 고장 아님 → 유선인데도 죽음 → 다른 USB 장치의 열거(enumeration) 방해 의심 → 키보드만 남기고 전부 분리 → 범인 검거: Xbox 무선 패드 리시버. Fast Boot 비활성화로 이중 해결. 키보드 없이 BIOS 진입은 sudo systemctl reboot --firmware-setup, OS 전환은 sudo grub2-reboot "항목명"이 유효한 우회로였다.
기본 부팅 OS 변경 명령이 안 듣는다
GRUB 항목명은 괄호까지 포함한 전체 문자열이 이름이다. "Windows Boot Manager"가 아니라 "Windows Boot Manager (on /dev/nvme0n1p1)". 정확한 이름은 grep ^menuentry /boot/grub2/grub.cfg | cut -d"'" -f2로 뽑고, 설정 후 grub2-editenv list로 검증. 숫자 인덱스는 커널 업데이트 시 순번이 밀리므로 이름 방식 권장.
GRUB에 리눅스가 3개나 보인다
정상 — ① 최신 커널(기본) ② 이전 커널(새 커널 문제 시 폴백, 기본 3개까지 보관) ③ 0-rescue(응급 구조 통로). 중복 설치가 아니라 커널 이력 관리이며, 업무 RHEL 서버에서도 동일하게 보게 될 구조다.
03

Windows 설치·설정

OOBE 관문과 배치·수명 관련 판단들.

MS 로그인 후 "백업된 설정 복원" 제안 — 받아야 하나
"새 장치로 설정"을 선택했다. 복원 범위는 개인 설정·Wi-Fi·앱 목록(프로그램 자체 아님)·시작 메뉴 배치, 그리고 OneDrive 폴더 백업 상태 — 마지막 것 때문에 거절이 정답. 이전 PC의 폴더 백업 상태가 따라오면 3중 방어로 막아둔 폴더 납치가 복원 경로로 재발한다. 클린 구축에서 잃는 것은 배경화면 수준.
사용자 폴더를 D:(SMR)로 옮겨도 되나
속성→위치 탭 방식은 공식 지원이라 안전하고, SMR에도 무해(간헐적·파일 단위 쓰기). 단 새 시스템에선 C:가 1.6TB라 전부 옮길 동기가 사라짐 — 부피형(다운로드·사진·동영상)만 D:, 소형·민감형(문서·바탕화면)은 C:의 선택적 이동으로 결정. 시점은 OneDrive 차단(KFMBlockOptIn) 완료 후.
단순 볼륨 만들기의 할당 단위(클러스터)는?
기본값 = 권장값. 크면 작은 파일의 슬랙 낭비, 작으면 대용량 볼륨 오버헤드 — 기본값이 균형점이다. 범용 공유 파티션엔 기본값이 정확히 맞고, XFS의 mkfs도 같은 원리로 기본값 사용.
SSD를 오래 쓰는 습관은? (교체 계기가 이전 SSD 수명 소진)
원리: 수명 = 쓰기 총량(TBW), 읽기는 무관, 실제 소모는 쓰기 증폭이 좌우. 효과 순 습관: ① 용량 15~20% 이상 항상 비워두기(최중요 — 이전 SSD의 사인으로 추정) ② 대량·반복 쓰기는 HDD로(계층화가 구조적으로 해결) ③ TRIM 확인(fsutil behavior query disabledeletenotify / fstrim.timer) ④ 온도(히트싱크로 대응됨) ⑤ 990 PRO 펌웨어 최신화(초기 펌웨어 수명 결함 이력 — Magician 확인) ⑥ 정상 종료. 페이지파일 끄기류 구형 최적화는 불필요, 벤치마크 반복은 순수 낭비. 모니터링: 반기 1회 TBW·잔여 수명 — 4TB 보증 2,400TBW면 산술상 수십 년.
04

RHEL 9.8 설치

Anaconda 관문들과 설치 직후 설정.

Red Hat 계정 연결의 "시스템 목적 설정"이란?
기업용 구독 매칭 라벨(역할/SLA/용도) — 자산 분류 메타데이터라 어떤 값이든 시스템 동작과 무관. 개인 Developer Subscription은 비워두면 됨. 설치 후 syspurpose로 변경 가능하고, 업무의 subscription-manager에서 재회할 개념.
/home이 계획(2.2TB)과 다른 1.87 TiB로 잡힌다
단위 효과 2중: ① 설치기는 2진(TiB) 표시 — 4TB 디스크 실총량 3.64 TiB ② diskpart에서 C:를 MB로 잘라 10진 1.76TB를 점유. 잔여 전부가 /home에 갔으므로 사라진 용량은 없음(10진 환산 약 2.06TB). "용량이 모자라 보이는" 착시의 전형 사례.
ESP가 "알 수 없음" 그룹에 남아 있었다 (중요)
수동 파티셔닝에서 4개 마운트만 추가하고 끝내면 부트로더 자리가 없다. 기존 EFI System Partition 클릭 → 마운트 지점 /boot/efi 지정 → 재포맷 절대 금지 → "신규 설치" 그룹으로 올라와야 완성. 완료 전 변경 요약에서 ESP가 "포맷" 목록에 없는지 최종 확인 — 이번 작업에서 사전에 잡아낸 유일한 "사고 직전" 항목.
변경 요약이 가이드와 다르다 — LVM이 나타났다
Anaconda 기본 장치 유형이 LVM이라 /·/home·swap이 "파티션 1개(PV) 안의 논리 볼륨 3개"로 구성됨(/boot은 부트로더가 직접 읽어야 해 자동으로 표준 파티션 분리). 용량·마운트는 계획 그대로이며 오히려 이득: LV는 나중에 크기 재배분 가능("굳는 경계"를 무르게) + 업무 RHEL 표준 구성과 동일한 모양(lvs/vgs 학습 기회).
Server with GUI vs Workstation
뼈대는 동일, 차이는 패키지 프리셋(관리 도구 vs 데스크톱·개발)과 tuned 프로파일(처리량 vs 균형). 이 머신의 정체는 개발용 데스크톱이므로 Workstation 선택. 비가역 아님 — 서버 도구는 dnf install cockpit 한 줄로 추가 가능.
추가 소프트웨어는 뭘 체크하나
개발용 툴 + 컨테이너 관리(Podman — 업무 환경 대비·Docker 비교 학습용) 2개만. 원칙: "나중에 한 줄로 추가할 수 있는 것은 지금 깔지 않는다" — 최소로 시작해야 뭐가 뭘 하는지 보이는 시스템이 된다.
root 계정 잠금 / root SSH 허용 체크박스
둘 다 체크 해제(root 비밀번호는 설정, SSH 거부는 RHEL 9 기본 유지). 근거: 업무 RHEL 재현(root 활성 구성) + 복구 상황의 보험(응급 모드가 root 비밀번호 요구). 일상은 관리자 사용자 + sudo, root는 금고에. — 이 선택이 이후 계정명 변경 작업에서 실제로 값을 했다.
150% 같은 비정수 배율이 안 보인다
GNOME의 비율 배율은 실험 기능: gsettings set org.gnome.mutter experimental-features "['scale-monitor-framebuffer']" 후 재로그인하면 125/150/175%가 나타남. XWayland(구형 X11) 앱은 흐릿할 수 있어, 거슬리면 대안은 텍스트만 확대(text-scaling-factor 1.5 — 항상 선명). NVIDIA 드라이버 설치 후 최종 판단.
설치 후 계정명을 바꿔도 되나
신규 설치 직후가 최적 타이밍. 제약은 "본인 로그인 중 rename 불가" — 로그아웃 → Ctrl+Alt+F3 콘솔에서 root 로그인 → usermod -l 새 기존 → groupmod -n → usermod -d /home/새 -m. 소유권은 UID 기반이라 자동 유지, wheel(sudo)도 자동 승계. 절차 중간에 그래픽 로그인 복귀 금지.
05

스토리지 · fstab

파티션 정체 확인부터 마운트 완성까지.

lsblk에 처음 보는 16M 파티션이 있다 (sda1, nvme0n1p2)
MSR(Microsoft 예약 파티션) — Windows가 GPT 디스크 초기화 시 자동 생성하는 관리용 예약 공간. 파일시스템·드라이브 문자 없음, blkid에서 Unknown으로 보이는 것까지 정상. 두 디스크에 하나씩 있는 게 맞으며 절대 삭제하지 않는다.
복사한 UUID는 fstab 어디에 넣나
파일 맨 아래 새 줄 — fstab은 한 줄 = 마운트 하나. 필드 6개의 의미: 장치(UUID — 장치명은 부팅마다 바뀔 수 있어 UUID가 표준) / 마운트 지점 / 파일시스템 / 옵션(nofail = 디스크 문제여도 부팅은 되게) / 덤프 0 / fsck 순서(루트 1, 나머지 2, NTFS는 0). 수동 입력 대신 echo "UUID=$(blkid -s UUID -o value /dev/sdX) ..." | sudo tee -a /etc/fstab 패턴이 오타를 원천 차단.
NTFS가 2개다 — Windows와 Shared 중 어느 UUID?
Shared(sda2). Windows C:는 의도적으로 제외 — 시스템 드라이브 상시 마운트는 빠른 시작/절전 잔여 상태와 얽혀 손상 위험이 있고, 두 OS의 접점은 공유 파티션 하나로 좁히는 설계이기도 하다. 라벨 지정 조회가 확실: blkid -t LABEL=Shared. NTFS의 UUID가 짧은 16진수인 것은 정상(파일시스템마다 형식 상이).
mount -a가 "failed to access mountpoint" 오류
fstab에 줄을 적어도 마운트 지점 디렉터리는 자동 생성되지 않는다 — mkdir 누락이 원인의 전부. 부수 확인 습관: fstab 수정 후 findmnt --verify로 사전 검사, mount -a가 조용히 끝나면 문법 검증 통과.
폴더 이름을 오타(shard)로 만들었다 — 안전한 삭제법
확인(ls -A, mount | grep) 후 sudo rmdir — 빈 디렉터리만 지울 수 있어 실수 방지가 내장된 삭제법. 내용물 확인 없이 날리는 rm -rf는 마운트 지점 관리에 쓰지 않는 습관.
아카이브 폴더 구조 잡기 — X300으로 이사할 건데 의미 있나
있다. 폴더 구조는 디스크가 아니라 /mnt/archive라는 경로에 속하며, Phase 9 이사가 rsync 복제 + fstab UUID 교체 방식이라 구조·데이터가 통째로 새 디스크에 안착하고 경로는 불변. "디스크에 폴더를 판다"가 아니라 "경로에 규칙을 세운다". 보완: chown으로 소유권을 사용자에게 — 매번 sudo로 파일 넣는 불편 방지.
06

교훈 요약 · 다음 단계

이번 세션을 관통한 패턴들.

  • 펌웨어 세계와 OS 세계는 다른 규칙으로 돈다 — 키보드(USB 열거), Secure Boot(키 관리), 부팅 항목(정확한 문자열). OS 상식이 통하지 않는 구간의 존재를 아는 것 자체가 문제 해결의 절반이었다.
  • 진단은 배제로 좁힌다 — "OS에선 됨 → 고장 아님", "유선인데도 죽음 → 장치 종류 아님", "하나만 남기고 전부 분리 → 범인 특정". 최소 구성 재현이 가장 빠른 길.
  • 이름·경로는 정확히 일치해야 한다 — GRUB 항목명(괄호 포함), fstab 마운트 지점(shard≠shared). 시스템은 유사 일치를 봐주지 않으며, 목록에서 복사하는 습관(grep·blkid -o value)이 오타 자체를 없앤다.
  • 단위 착시를 알면 놀라지 않는다 — TB(10진) vs TiB(2진), MB 절사. "용량이 사라졌다"의 대부분은 계산이 맞다는 뜻.
  • 기본값은 대부분 정답이다 — BIOS 전압, 할당 단위, LVM 구성. 벗어날 때는 이유가 있을 때만(Secure Boot·CSM·Fast Boot이 그 예외였다).
  • 안전장치는 미리 심어둔다 — nofail, rmdir, 재포맷 금지 확인, root 비밀번호 보유, 구 디스크 보관. 실제로 이번에 root와 grub2-reboot가 각각 한 번씩 값을 했다.
