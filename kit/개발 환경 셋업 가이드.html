버전 정책 — 먼저 이해하고 시작

이 가이드의 버전 선택에는 이유가 있습니다. 여기만 읽으면 나머지는 손이 가는 대로.

Java는 21 하나로 — JDK 8은 설치하지 않는다
  • JDK 21 (LTS) 단일 구성. 미니PJ의 Spring Boot 3.x가 Java 17 이상 필수이고, VSCode Java 확장(언어 서버) 구동에도 17+가 필요합니다 — 21 하나가 전부를 충족합니다.
  • JDK 8을 개인 환경에 두지 않는 이유: 업무 8 경험은 회사에서 매일 쌓이므로 재현 가치가 낮고, 이중 JDK는 JAVA_HOME 전환·보안 패치·IDE 런타임 설정이라는 관리 포인트만 늘립니다. 관리 대상 최소화 원칙.
  • 8 언어 레벨 확인이 정말 필요해지는 순간이 오면(예: 회사 코드 조각 검증) 그때 sdk install java 8.0.x-tem(SDKMAN) 한 줄로 일시 추가하면 됩니다 — 지금 미리 깔 이유가 없습니다.
Python 3.12.7 — "정확히 그 버전"을 잡는 법
  • Windows: python.org에 3.12.7 설치본이 아카이브로 남아 있어 그대로 설치.
  • RHEL: dnf의 python3.12는 최신 패치(3.12.x)로 계속 움직여서 .7 고정이 안 됩니다. 그래서 pyenv로 3.12.7을 소스 빌드해 고정합니다 — 버전 고정이 필요한 환경에서 쓰는 표준 방식이고, 나중에 다른 버전 병행도 자유로워집니다.
C++11 — 컴파일러는 넉넉하고, 표준 플래그로 고정
  • RHEL 9.8 기본 GCC 11, MSYS2의 GCC 최신판 모두 C++11을 완전 지원합니다. 별도 구버전 컴파일러가 필요한 게 아니라, 빌드 시 -std=c++11 플래그로 표준을 고정하는 방식입니다(업무 코드 호환 확인용). VSCode 설정에 포함해뒀습니다.
  • Windows에서 MSVC(Visual Studio) 대신 MSYS2 GCC를 쓰는 이유: 업무·개발 OS가 Linux/GCC 계열이므로 같은 컴파일러 계열로 맞추면 양쪽 동작 차이를 신경 쓸 일이 없습니다.

Windows — 언어 3종 + 기본 도구 WINDOWS

winget(기본 내장 패키지 관리자)으로 대부분 한 줄씩 끝냅니다. 터미널은 시작 우클릭 → 터미널(관리자).

winget install --id Git.Git -e
winget install --id Microsoft.VisualStudioCode -e
  • 설치 후 새 터미널에서 git --version 확인. 사용자 설정:
git config --global user.name  "이름"
git config --global user.email "본인@이메일"
git config --global core.autocrlf true    # Windows 쪽 개행 처리 표준
winget install --id MSYS2.MSYS2 -e
  1. 시작 메뉴에서 MSYS2 UCRT64 셸 실행 후:
pacman -Syu                    # 첫 실행 시 셸이 닫히면 다시 열어 한 번 더
pacman -S mingw-w64-ucrt-x86_64-toolchain \
          mingw-w64-ucrt-x86_64-cmake \
          mingw-w64-ucrt-x86_64-gdb
  1. PATH 등록: 설정 → 시스템 → 정보 → 고급 시스템 설정 → 환경 변수 → Path에 C:\msys64\ucrt64\bin 추가.
  2. 새 터미널에서 확인: g++ --version · gdb --version · cmake --version
TIP업무 코드가 MSVC(Visual Studio) 기반으로 판명되면 그때 winget install Microsoft.VisualStudio.2022.BuildTools를 추가하면 됩니다. 지금은 GCC 계열 통일이 학습 효율상 정답.
winget install --id Python.Python.3.12 -e --version 3.12.7
  • 또는 python.org/downloads/release/python-3127 에서 "Windows installer (64-bit)" 직접 설치 — 이때 "Add python.exe to PATH" 체크 필수.
  • 확인: python --version → Python 3.12.7. 프로젝트별 가상환경은 python -m venv .venv 습관을 권장.
winget install --id EclipseAdoptium.Temurin.21.JDK -e
  • JAVA_HOME 환경 변수를 C:\Program Files\Eclipse Adoptium\jdk-21... 경로로 등록.
  • 확인: 새 터미널에서 java -version → 21.x 출력.
  1. maven.apache.org/download → Binary zip archive 다운로드 → C:\tools\apache-maven-3.9.x에 압축 해제.
  2. 환경 변수 Path에 C:\tools\apache-maven-3.9.x\bin 추가.
  3. 확인: mvn -v — Java version이 21로 나오면 정상(JAVA_HOME을 따라감).

RHEL 9.8 — 언어 3종 LINUX

선행: subscription-manager 등록 + EPEL 활성화(듀얼부팅 가이드 Phase 5). 모두 터미널 작업입니다.

sudo dnf group install "Development Tools"   # gcc·g++·make·git 등 일괄
sudo dnf install gdb cmake
  • 확인: g++ --version(11.x) · gdb --version · cmake --version
  • C++11 컴파일은 g++ -std=c++11 -g main.cpp — -g는 GDB 디버깅 심볼.
TIP나중에 최신 GCC가 필요해지면 병행 설치가 가능합니다: sudo dnf install gcc-toolset-14 후 scl enable gcc-toolset-14 bash로 그 셸에서만 활성화. 기본 GCC 11은 그대로 유지됩니다.
# 1) 소스 빌드 의존성
sudo dnf install zlib-devel bzip2 bzip2-devel readline-devel sqlite \
  sqlite-devel openssl-devel tk-devel libffi-devel xz-devel

# 2) pyenv 설치
curl -fsSL https://pyenv.run | bash

# 3) 셸 연동 — ~/.bashrc 끝에 추가
export PYENV_ROOT="$HOME/.pyenv"
export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init -)"

# 4) 새 터미널 열고 3.12.7 빌드·기본 지정
pyenv install 3.12.7
pyenv global 3.12.7
python --version        # Python 3.12.7
  • 시스템 파이썬(/usr/bin/python3, 3.9)은 OS 도구용으로 그대로 두고 건드리지 않습니다 — pyenv가 사용자 영역에서만 우선순위를 갖는 안전한 구조입니다.
sudo dnf install java-21-openjdk-devel
java -version                      # 21.x 확인
  • 단일 JDK 구성이라 alternatives 전환도 불필요합니다. 언젠가 다른 버전이 잠깐 필요해지면 SDKMAN(sdk install java)으로 일시 추가 — 시스템 JDK는 21 하나로 유지.
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install maven
sdk install gradle          # 선택 — Spring Initializr에서 Gradle 프로젝트를 만들 경우
mvn -v
  • SDKMAN은 Java 생태계 도구의 버전 관리자입니다(pyenv의 Java판). 나중에 특정 Maven/Gradle 버전 고정이 필요할 때도 sdk use로 해결됩니다.

RHEL 전용 — 플랫폼 스택 LINUX

Node.js · Docker · 미니PJ용 DB까지. 개발용 OS에만 설치하는 것들입니다.

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# 새 터미널 열고:
nvm install --lts
node -v && npm -v
  • nvm은 Node 버전 관리자입니다. 목표 회사의 Node 버전을 알게 되면 nvm install 그버전 한 줄로 병행 설치·전환 가능 — 지금은 최신 LTS로 시작.
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf install docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER      # 로그아웃/로그인 후 적용
docker run hello-world             # 재로그인 후 sudo 없이 되는지 확인
참고 — PodmanRHEL에는 Podman이 기본 탑재되어 있고 업무 환경에서 만날 가능성이 높습니다. 명령이 Docker와 거의 동일해서(alias docker=podman이 통할 정도) Docker로 익히면 그대로 전이됩니다. CI/CD 연습은 생태계가 넓은 Docker 기준으로 진행.
  • 로컬 설치 대신 컨테이너로 — 미니PJ의 Docker 연습 목적과도 맞고, 초기화가 깨끗합니다. swe-projects/url-shortener/docker-compose.yml:
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: shortener
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: devpass   # 로컬 전용 — 공개 레포에 실비밀번호 금지
    ports: ["5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]
  cache:
    image: redis:7
    ports: ["6379:6379"]
volumes:
  pgdata:                          # NVMe(홈 디렉터리) 볼륨 — HDD 금지 원칙 준수
docker compose up -d
docker compose ps                  # db·cache 모두 running 확인
  • Spring은 별도 설치물이 없습니다. JDK 21 + Maven이 곧 Spring 개발 환경이고, 프로젝트는 start.spring.io(Spring Initializr)에서 생성합니다.
  • 미니PJ 시작 시 선택값: Maven · Java 21 · Spring Boot 3.x · Dependencies: Spring Web, Spring Data JPA, PostgreSQL Driver, Spring Data Redis, Validation.
  • 생성된 zip을 swe-projects/url-shortener/server/에 풀고 ./mvnw spring-boot:run으로 기동 확인.

VSCode — 확장과 설정 WINLINUX

양쪽 OS 동일하게 세팅합니다. RHEL 쪽 설치부터, 그다음 공통 확장·설정.

sudo rpm --import https://packages.microsoft.com/keys/microsoft.asc
sudo tee /etc/yum.repos.d/vscode.repo << 'EOF'
[code]
name=Visual Studio Code
baseurl=https://packages.microsoft.com/yumrepos/vscode
enabled=1
gpgcheck=1
gpgkey=https://packages.microsoft.com/keys/microsoft.asc
EOF
sudo dnf install code
TIP — 설정 동기화VSCode의 Settings Sync(GitHub/MS 계정)를 켜두면 Windows에서 세팅한 확장·설정이 RHEL 쪽에 자동 복제됩니다. 두 번 세팅할 필요가 없어져요.
  • 터미널에서 일괄 설치(양쪽 OS 공통):
code --install-extension ms-vscode.cpptools-extension-pack   # C++ + CMake Tools
code --install-extension ms-python.python                    # Python + Pylance + debugpy
code --install-extension vscjava.vscode-java-pack            # Java 필수 6종
code --install-extension vmware.vscode-boot-dev-pack         # Spring Boot 지원
code --install-extension ms-azuretools.vscode-containers     # 컨테이너 관리
code --install-extension eamodio.gitlens                     # Git 히스토리 심화
code --install-extension dbaeumer.vscode-eslint              # Node/JS 린트 (RHEL)
  • Ctrl+Shift+P → "Open User Settings (JSON)" → 아래 병합:
{
  // Java: 단일 JDK 21 — JAVA_HOME이 잡혀 있으면 자동 인식되어 이 줄도 생략 가능
  "java.jdt.ls.java.home": "JDK21 경로",
  // C++: 표준을 C++11로 고정
  "C_Cpp.default.cppStandard": "c++11",
  "C_Cpp.default.cStandard": "c11",
  // Python: 저장 시 자동 포맷 없는 담백한 시작
  "python.terminal.activateEnvironment": true
}
JDK 21 경로
WindowsC:\Program Files\Eclipse Adoptium\jdk-21...
RHEL/usr/lib/jvm/java-21-openjdk
  • 단일 JDK 구성이라 런타임 매핑 설정 없이도 언어 서버·컴파일 모두 21로 일관됩니다.

IntelliJ IDEA 설치·구성 WINLINUX

업무 도구가 IntelliJ 체제로 정렬됨에 따라 개인 환경도 동일 도구로 맞춥니다(도구 패리티). 역할 분담: VSCode = 범용 주력(C++·Python·Vue·스크립트), IntelliJ = Java/Spring 전용(미니PJ 서버). 무료 범위(Community 기능)로 충분 — Ultimate 결제는 불요.

winget install --id JetBrains.IntelliJIDEA.Community -e
  • 2025.3부터 IntelliJ는 Community/Ultimate 구분이 없는 통합 배포판(무료 모드 포함)으로 바뀌었습니다. winget 검색 결과가 통합판 단일 항목으로 보이면 그걸 설치하면 됩니다 — 무료 모드가 기존 Community 기능을 그대로 포함합니다.
# jetbrains.com에서 Linux용 tar.gz 다운로드 후:
sudo tar -xzf idea*.tar.gz -C /opt/
sudo mv /opt/idea-* /opt/idea
/opt/idea/bin/idea.sh              # 첫 실행
  • 첫 실행 후 Tools → Create Desktop Entry로 앱 목록에 등록하면 이후 GNOME에서 바로 실행됩니다.
  • 대안: JetBrains Toolbox App을 먼저 깔고 그 안에서 IntelliJ를 설치하면 업데이트가 자동 관리됩니다 — 버전 관리를 도구에 맡기고 싶으면 이쪽.
  1. JDK 등록: File → Project Structure → SDKs → +로 Phase 1·2에서 설치한 JDK 21 등록(대부분 자동 감지됨). 프로젝트 SDK·Language level 모두 21.
  2. 미니PJ 열기: swe-projects/url-shortener/server의 pom.xml 기준으로 Open — Maven 설정은 개인 환경이므로 기본(~/.m2) 그대로면 됩니다.
  3. Settings Sync: JetBrains 계정으로 로그인해 설정 동기화를 켜면 Windows↔RHEL 양쪽 IntelliJ가 자동으로 같은 상태를 유지합니다(VSCode Settings Sync와 동일 개념).
  4. (선택) Python 지원: 통합판에 동봉된 Python 플러그인을 활성화하고 인터프리터로 pyenv의 3.12.7(~/.pyenv/versions/3.12.7/bin/python)을 지정하면 Java·Python을 한 창에서 다룰 수 있습니다.
역할 정리일상 편집·Vue·스크립트·C++ 연습은 VSCode, Spring Boot 서버 작업(미니PJ ①~④ 구현·디버깅·리팩터링)은 IntelliJ — 두 IDE가 같은 폴더를 열어도 충돌하지 않으므로(.idea는 IntelliJ 개인 영역) 작업 성격에 따라 골라 쓰면 됩니다.

이 조합에서 실제로 자주 만나는 것들.

VSCode Java 확장이 "Java 17 이상이 필요합니다" 오류를 내요
언어 서버가 JDK를 못 찾거나 다른 JVM을 물었을 때 나는 오류입니다. JAVA_HOME이 JDK 21을 가리키는지, 또는 settings.json의 java.jdt.ls.java.home이 21 경로인지 확인 → VSCode 재시작.
pyenv install 3.12.7이 빌드 중 실패해요
십중팔구 의존성 누락입니다. Phase 2의 dnf install zlib-devel ... xz-devel 블록을 다시 실행하고 재시도하세요. 로그에 ssl이 보이면 openssl-devel, _lzma면 xz-devel 누락입니다.
docker 명령이 permission denied라고 해요
usermod -aG docker는 재로그인해야 적용됩니다. 로그아웃/로그인(또는 재부팅) 후 groups 명령에 docker가 보이는지 확인하세요.
Windows 터미널에서 g++를 못 찾아요
PATH에 C:\msys64\ucrt64\bin이 등록됐는지, 등록 후 터미널을 새로 열었는지 확인하세요(기존 창엔 반영 안 됨). MSYS2 셸 안에서만 되고 일반 터미널에서 안 되면 100% PATH 문제입니다.
mvn이 이상한 Java 버전을 물고 있어요
Maven은 JAVA_HOME을 따라갑니다. echo $JAVA_HOME(Windows: echo %JAVA_HOME%)으로 확인하고 JDK 21 경로로 바로잡으세요. 단일 JDK 구성에선 JAVA_HOME=21 고정이 전부입니다.
