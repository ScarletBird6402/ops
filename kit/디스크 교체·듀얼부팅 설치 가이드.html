준비물 — 디스크 빼기 전에 끝낼 것

지금 PC가 살아있을 때만 할 수 있는 작업들입니다. 이 단계를 건너뛰면 주말에 되돌아와야 합니다.

  • 기존 C·D 드라이브에서 남길 데이터를 외장 디스크나 클라우드로 백업합니다. 수명 문제가 있는 디스크이므로 이번 백업이 마지막 기회라고 생각하고 꼼꼼히.
  • 놓치기 쉬운 것: 브라우저 북마크, 게임 세이브(문서·AppData 폴더), FL Studio 정품 인증 파일·프로젝트, SSH 키, .gitconfig.
TIP기존 디스크는 포맷하지 말고 당분간 서랍에 보관하세요. 새 시스템이 안정되기 전까지가 진짜 백업 기간입니다.
  • 로컬 클론들에서 git status · git log origin/main..HEAD로 커밋 안 된 변경·push 안 된 커밋이 있는지 확인 후 전부 push합니다. GitHub에 올라간 것만 디스크 교체에서 살아남습니다.
  • 아직 원격 레포가 없는 작업물(초기 세팅 파일 등)은 zip으로 외장/클라우드에 보관.
확인각 레포에서 git status가 clean이고 ahead 표시가 없으면 완료.
  • 현재 Windows에서 제어판 → BitLocker 드라이브 암호화 확인. 켜져 있다면 복구 키를 다른 기기(폰 메모·출력물)에 저장.
  • Microsoft 계정으로 로그인 중이면 account.microsoft.com/devices/recoverykey 에서도 확인 가능합니다.
  • Windows 11: 8GB 이상 USB에 Microsoft 미디어 생성 도구(Media Creation Tool)로 제작. (microsoft.com → Windows 11 다운로드)
  • Linux: 별도의 8GB 이상 USB에 ISO를 굽습니다. 배포판은 RHEL 9 또는 Rocky Linux 9 — 차이와 선택 기준은 Phase 5 첫머리에 정리해뒀습니다. 굽는 도구는 Rufus 권장(ISO 선택 후 기본값 GPT/UEFI로 시작).
  • ISO 받는 곳 — Rocky: rockylinux.org / RHEL: developers.redhat.com에서 무료 Developer Subscription 가입 후 다운로드(개인 개발 용도 16시스템까지 무료).
TIP — 설치 당일에 고르고 싶다면USB는 배포판 하나만 담기므로, 둘 다 후보로 두려면 Ventoy(ventoy.net)로 USB를 만들고 그 안에 두 ISO 파일을 그냥 복사해 넣으세요. 부팅 시 메뉴에서 ISO를 골라 설치할 수 있습니다(Windows ISO까지 한 USB에 넣는 것도 가능).
주의USB는 두 개를 따로 쓰세요. 하나에 겹쳐 구우면 중간에 다시 구울 방법이 없습니다(PC에 OS가 없는 상태이므로).
  • 십자드라이버(#2), 밝은 조명, 부품 나사 담을 그릇.
  • 이 가이드를 폰에 저장(HTML 파일 그대로 열립니다) 또는 인쇄. 설치 중에는 PC로 볼 수 없습니다.
  • 메인보드 매뉴얼에서 M.2 슬롯 위치와 SATA 포트 배치 페이지를 미리 펴두면 좋습니다(모델명은 케이스 옆면 보드에 인쇄되어 있음).
01

물리 교체 HARDWARE

전원만 확실히 차단하면 레고 조립 수준입니다. 서두르지 않는 게 유일한 요령.

  1. Windows 완전 종료 → 파워서플라이 뒤 스위치 OFF → 전원 케이블 분리.
  2. 전원 버튼을 5초간 눌러 잔류 전기를 방전.
  3. 작업 전 케이스 금속부를 한 번 만져 정전기를 빼고, 카펫 위 작업은 피합니다.
  • 케이스 옆판 개방(뒤쪽 손나사 2개가 보통).
  • 분리 전에 케이블 연결 상태를 폰으로 촬영 — 나중에 그대로 복원할 기준 사진이 됩니다.
  • 기존 SATA 디스크: 데이터 케이블(얇은 것)·전원 케이블(넓은 것) 분리 → 베이 나사 제거 → 탈거.
  • 기존 M.2가 있다면: 끝단 고정 나사(또는 래치) 해제 → 30도 각도로 들려 올라오면 슬롯에서 빼기.
  • CPU에 가장 가까운 M.2 슬롯(보통 M.2_1)에 장착 — CPU 직결 레인이라 990 PRO의 PCIe 4.0 성능이 온전히 나옵니다.
  • 30도 각도로 홈을 맞춰 끝까지 삽입 → 눌러서 나사/래치 고정. 금색 단자가 보이면 덜 들어간 것.
주의구매하신 모델은 히트싱크 일체형(with Heatsink)입니다. 메인보드에 붙어 있는 M.2 방열판은 장착하지 마세요(이중 장착 불가·간섭). 보드 방열판은 분리해 보관.
  • 3.5인치 베이에 넣고 양옆 나사(또는 트레이) 고정. 진동 소음 방지를 위해 나사 4개 모두 체결 권장.
  • SATA 데이터 케이블: HDD ↔ 메인보드 SATA 포트. 촬영해둔 사진의 포트를 그대로 쓰면 됩니다.
  • SATA 전원 케이블: 파워서플라이에서 나온 넓적한 커넥터 연결.
TIP일부 보드는 특정 SATA 포트가 M.2와 레인을 공유해 비활성화되는 경우가 있습니다. HDD가 인식 안 되면 다른 SATA 포트로 옮겨 보세요(문제 해결 섹션 참고).
  • 옆판을 닫기 전에 전원을 연결하고 켜서 BIOS에서 두 디스크가 보이는지만 먼저 확인(Phase 2)하면, 케이스를 두 번 열 일이 없습니다.
02

BIOS 확인 FIRMWARE

설치 전에 3가지만 확인합니다. 인식 · UEFI · Secure Boot.

  • 전원을 켜자마자 Del 또는 F2 연타 → BIOS 진입.
  • Storage / NVMe / SATA 정보 화면에서 Samsung 990 PRO 4TB와 ST8000DM004(BarraCuda)가 모두 보이는지 확인.
  • Boot 메뉴에서 CSM(Compatibility Support Module)이 Disabled인지 확인. 13세대 시스템은 대부분 기본 UEFI입니다.
  • Security(또는 Boot) 메뉴에서 Secure Boot → Disabled.
  • 켠 채로도 설치는 가능하지만, Linux에서 RTX 4080용 NVIDIA 드라이버를 올릴 때 MOK 서명 등록이라는 추가 절차가 필요해집니다. 처음이라면 끄는 쪽이 확실히 수월합니다.
  • 변경 후 F10 저장·재부팅.
03

Windows 11 설치 WINDOWS

순서가 중요합니다 — 반드시 Windows 먼저, Linux는 나중. ESP(부트 파티션)를 1GB로 직접 만드는 것이 이 단계의 핵심.

왜 Windows 먼저?Linux의 부트로더(GRUB)는 설치 시 Windows를 자동 감지해 부팅 메뉴에 넣어주지만, 반대는 안 됩니다. 또 Windows 설치기는 기본 100MB짜리 부트 파티션(ESP)을 만드는데, 두 OS가 같이 쓰기엔 빠듯해서 1GB로 직접 만들어줍니다.
  • USB 꽂고 전원 ON → F11(부트 메뉴, 보드에 따라 F8/F12) → UEFI: USB이름 선택.
  • 설치 유형은 사용자 지정(Custom) 선택.
실수 방지 TIP설치 대상 실수를 원천 차단하고 싶다면 이 단계에서 HDD의 SATA 데이터 케이블을 잠시 뽑아두는 것도 좋은 방법입니다(초보자 정석 요령). Windows 설치 후 다시 꽂으면 됩니다.
  • 파티션 선택 화면에서 Shift+F10 → 명령 프롬프트가 열립니다. 아래를 한 줄씩 입력:
diskpart
list disk                 # 디스크 목록 — "3726 GB"가 990 PRO
select disk N             # N = 위에서 확인한 4TB NVMe 번호!
clean                     # ⚠ 선택한 디스크 전체 삭제
convert gpt
create partition efi size=1024
format quick fs=fat32 label=System
create partition msr size=16
create partition primary size=1677722   # C: 1.6TB
format quick fs=ntfs label=Windows
exit
exit
주의 — 여기가 이 가이드에서 가장 조심할 지점select disk N의 번호는 반드시 본인 화면의 list disk 결과에서 크기(3726 GB)로 확인한 번호를 쓰세요. 8TB HDD(7452 GB)를 선택한 채 clean하면 안 됩니다. 새 디스크라 잃을 데이터는 없지만, 습관을 처음부터 바르게.
  • 완료 후 설치 화면에서 새로 고침 → Windows(1.6TB, NTFS) 파티션을 선택해 설치 진행.
  • 남은 약 2.4TB는 할당하지 않은 공간 그대로 둡니다 — Linux 몫입니다.
  • 계정·지역 설정을 진행하다 보면 "OneDrive를 사용하여 파일 백업" 류의 화면이 나옵니다. 여기서 반드시 "이 PC에만 파일 저장"(또는 "지금은 안 함")을 선택 — 여기서 "다음/백업"을 누르는 순간 문서·바탕화면·사진 폴더 경로가 OneDrive 밑으로 넘어갑니다.
  • 화면 문구는 버전에 따라 조금씩 다르지만, OneDrive라는 단어가 보이면 일단 거부가 원칙. 놓쳤더라도 Phase 4 첫 단계에서 복구·차단할 수 있으니 당황하지 않아도 됩니다.
  • 바탕화면 진입이 되면 Phase 4로.
04

Windows 초기 설정 WINDOWS

듀얼부팅 안정성을 좌우하는 설정 2가지 + 드라이버. Linux 설치 전에 끝냅니다.

  • 다른 무엇보다 먼저, 문서·게임 세이브 폴더가 쌓이기 전에 처리합니다. 순서대로:
  1. 레지스트리로 원천 차단(재발 방지 핵심) — 시작 버튼 우클릭 → 터미널(관리자) 실행 후: 
    reg add HKLM\SOFTWARE\Policies\Microsoft\OneDrive /v KFMBlockOptIn /t REG_DWORD /d 1 /f
    이 정책(KFM 차단)이 있으면 OneDrive가 알림·자동 설정 어느 경로로도 알려진 폴더(문서/바탕화면/사진)를 자기 밑으로 옮길 수 없게 됩니다. 타이밍을 놓치는 문제 자체가 사라집니다.
  2. 현재 상태 확인 — 문서 폴더 우클릭 → 속성 → 위치 탭. 경로가 C:\Users\사용자명\Documents면 정상. ...\OneDrive\문서로 되어 있다면 이미 넘어간 상태 → 3번으로.
  3. 이미 넘어간 경우 되돌리기 — 작업표시줄 OneDrive 아이콘 → 설정 → 동기화 및 백업 → 백업 관리 → 문서·사진·바탕화면 모두 백업 중지. 그다음 각 폴더 속성 → 위치 탭 → 기본값 복원 → 파일 이동 여부를 물으면 "예".
  4. (선택) OneDrive 자체가 필요 없다면 — 설정 → 앱 → 설치된 앱에서 Microsoft OneDrive 제거. 1번 정책을 넣어뒀다면 남겨둬도 폴더를 건드리지는 못합니다.
확인문서 폴더 속성 → 위치가 C:\Users\...로 시작하고, OneDrive 백업 관리에서 세 폴더가 모두 꺼져 있으면 완료. 이후 설치할 프로그램·게임 세이브가 전부 로컬 경로에 안착합니다.
  • 제어판 → 전원 옵션 → 전원 단추 작동 설정 → 현재 사용할 수 없는 설정 변경 → "빠른 시작 켜기" 체크 해제 → 저장.
  • 켜둔 채 Linux에서 NTFS(공유 파티션)를 건드리면 파일시스템이 손상될 수 있습니다. 듀얼부팅의 1순위 필수 설정.
  • Windows 11은 조건에 따라 장치 암호화를 자동으로 켭니다. 설정 → 개인 정보 및 보안 → 장치 암호화 확인.
  • 켜져 있으면: 복구 키를 백업해두거나, 듀얼부팅 중 복구 화면이 뜨는 게 번거로우면 끄는 것도 선택지(집 데스크톱이면 무방).
  • nvidia.com에서 RTX 4080용 Game Ready(또는 Studio) 드라이버 설치. FL Studio를 쓰신다면 Studio 드라이버도 좋은 선택.
  • Windows 업데이트를 한 차례 완료해 두면 이후 업데이트가 부트 영역을 건드릴 확률이 줄어듭니다.

  • RHEL 추천 상황: 현재 업무가 RHEL이고, subscription-manager 같은 실무 절차까지 그대로 경험하고 싶을 때.
  • Rocky 추천 상황: 등록·갱신 관리 없이 학습 자체에 집중하고 싶을 때. 학습 내용은 RHEL에 그대로 통합니다.
  • 아래 설치 절차는 양쪽 공통이며, 다른 부분(등록·저장소 명령)만 RHEL / ROCKY 표시로 구분해뒀습니다.
  • F11 부트 메뉴 → UEFI: USB 선택 → "Install Rocky Linux 9" 또는 "Install Red Hat Enterprise Linux 9" 진입.
  • 언어는 한국어/영어 편한 쪽으로. 설치 요약 화면에서 설치 대상(Installation Destination) 선택.
  • RHEL 설치 요약에 "Connect to Red Hat" 항목이 있습니다. 인터넷이 연결돼 있다면 여기서 Red Hat 계정으로 등록해두는 게 가장 간편합니다(건너뛰었다면 설치 후 아래 명령으로):

HDD 8TB 파티셔닝 WINLINUX

NTFS(공유·게임) 4.5TB는 Windows에서, XFS(아카이브) 3.5TB는 Linux에서 만듭니다.

  1. Windows로 부팅 → Win+X → 디스크 관리.
  2. 8TB 디스크 초기화 팝업이 뜨면 GPT 선택.
  3. 할당되지 않은 영역 우클릭 → 새 단순 볼륨 → 크기 4718592 MB(=4.5TB) → 드라이브 문자 D: → NTFS 빠른 포맷, 볼륨 레이블 Shared.
  4. 남은 ~3.5TB는 그대로 둡니다(Linux 몫).
  • Linux로 부팅 후 터미널에서:
# 1) HDD 장치명 확인 — 7.3T 디스크가 대상 (보통 sda)
lsblk

# 2) 남은 공간에 파티션 생성 (sdX를 실제 장치명으로!)
sudo parted /dev/sdX -- mkpart archive xfs 4.5TB 100%

# 3) XFS 포맷 (파티션 번호 확인 — 보통 sdX2)
sudo mkfs.xfs -L archive /dev/sdX2

# 4) 마운트 지점 + 부팅 시 자동 마운트
sudo mkdir -p /mnt/archive
sudo blkid /dev/sdX2          # UUID 복사
sudo nano /etc/fstab           # 아래 한 줄 추가
UUID=복사한-UUID  /mnt/archive  xfs  defaults,nofail  0 2
sudo systemctl daemon-reload
sudo mount -a
df -h /mnt/archive             # 3.2T 근처로 보이면 성공
TIPnofail 옵션은 HDD에 문제가 생겨도 부팅 자체는 되게 해주는 안전장치입니다. 아카이브 디스크에는 항상 붙이는 습관을 권장.
sudo dnf install ntfs-3g       # EPEL 저장소 필요 (Phase 5에서 설치함)
sudo mkdir -p /mnt/shared
sudo blkid | grep -i ntfs      # NTFS 파티션 UUID 확인
# /etc/fstab에 추가:
UUID=NTFS-UUID  /mnt/shared  ntfs-3g  defaults,nofail,windows_names  0 0
  • windows_names는 Windows에서 못 쓰는 파일명 생성을 막아 양쪽 호환을 지켜줍니다.
mkdir -p /mnt/archive/{ai-models,datasets,db-backups,cold-logs}
  • AI 모델·데이터셋·DB 덤프·콜드 로그의 자리를 미리 만들어두면 "느린 잉여 공간"이 되는 걸 막을 수 있습니다. 라이브 DB 데이터·Docker 볼륨·학습 체크포인트는 여기 두지 않기(SMR 특성).

X300 4TB 편입 — 백업 체계 완성 HWWINLINUX

새 시스템 안정화 후(1~2주 뒤) 별도 진행. 기존 HDWR440(X300, CMR)을 아카이브 전담으로 편입하고, 8TB의 임시 아카이브 영역을 백업으로 전환합니다. 역할 근거: 아카이브는 혼합 쓰기(모델 교체·덤프 로테이션)라 CMR 적임, 백업은 순차 대용량 쓰기라 SMR 적임.

  • X300에는 구 시스템 데이터가 들어 있습니다. 새 시스템에서 1~2주 실사용하며 빠진 파일이 없음을 확인한 뒤에만 이 단계로 진행하세요 — 여기서 포맷하면 마지막 안전망이 사라집니다.
  • USB 어댑터나 임시 SATA 연결로 물려 CrystalDiskInfo로 SMART 확인: 재할당 섹터(05)·대기 섹터(C5)·회복 불가 섹터(C6)가 0이면 신뢰 역할 부여 가능. 수치가 있으면 백업/아카이브 역할 모두 재고.
  • Phase 1의 8TB 장착과 동일: 3.5" 베이 + SATA 데이터·전원. 나사 4개 체결 권장 — X300은 7200RPM이라 쓰기 시 딸깍 소음이 있는 모델이므로 방진 마운트/와셔가 있으면 사용.
  • BIOS에서 3개 디스크 인식 확인.
# 1) X300 확인·파티셔닝·포맷 (7.2TB=8TB와 혼동 금지 — 3.6T 디스크가 X300)
lsblk
sudo parted /dev/sdY -- mklabel gpt mkpart archive xfs 1MiB 100%
sudo mkfs.xfs -L archive-x300 /dev/sdY1

# 2) 임시 마운트 후 기존 아카이브 데이터 이사 (검증 포함)
sudo mkdir -p /mnt/newarchive && sudo mount /dev/sdY1 /mnt/newarchive
sudo rsync -aHv --info=progress2 /mnt/archive/ /mnt/newarchive/
sudo rsync -aHc --dry-run /mnt/archive/ /mnt/newarchive/   # 체크섬 검증 — 출력 없으면 완전 일치

# 3) fstab 교체: /mnt/archive가 X300(새 UUID)을 가리키도록 수정 후 재마운트
sudo blkid /dev/sdY1
sudo nano /etc/fstab      # /mnt/archive 행의 UUID를 새 값으로, nofail 유지
sudo umount /mnt/archive /mnt/newarchive && sudo mount -a
df -h /mnt/archive        # 3.6T 근처면 전환 완료
  • 이사가 끝난 8TB의 구 아카이브 파티션(3.5TB XFS)을 삭제하고 둘로 재분할합니다:

  • /mnt/backup은 fstab에 nofail로 등록(아카이브와 동일 패턴).
  • 백업 대상 원칙: 재생성 불가능한 것만. 게임(재다운로드)·AI 모델 원본(재다운로드)은 제외, 문서·프로젝트·개발 데이터·자체 생산 아카이브는 포함.
  • WIN ① 파일 히스토리: 설정 → 백업에서 대상 드라이브를 WinBackup으로 → 자동 주기 백업. ② 시스템 이미지: 제어판 → 백업 및 복원(Windows 7) → 시스템 이미지 만들기 → WinBackup 대상 — 분기 1회 수동이면 충분.
  • LINUX rsync 스냅샷 타이머 (매일 03시 예시):

sudo tee /etc/systemd/system/backup-home.timer << 'EOF'

sudo systemctl enable --now backup-home.timer
systemctl list-timers backup-home.timer   # 다음 실행 시각 보이면 가동 중

문제 해결

주말에 실제로 만날 확률이 높은 순서대로.

BIOS에서 HDD(또는 NVMe)가 안 보여요
① SATA 데이터·전원 케이블 재장착(딸깍 소리 확인) ② 다른 SATA 포트로 이동 — 일부 보드는 M.2 사용 시 특정 SATA 포트가 비활성화됩니다(매뉴얼의 M.2 레인 공유 표 확인) ③ M.2는 나사를 풀고 재삽입(금색 단자가 안 보일 때까지).
GRUB 메뉴에 Windows가 안 나와요
Linux 부팅 후: 
sudo nano /etc/default/grub
# 파일 끝에 추가:  GRUB_DISABLE_OS_PROBER=false
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
sudo reboot
부팅하면 GRUB 없이 바로 Windows로 들어가요
BIOS 부팅 순서에서 rocky(또는 redhat) 항목을 Windows Boot Manager보다 위로 올리세요. GRUB이 1순위가 되어야 선택 메뉴가 뜹니다.
Windows 부팅 시 BitLocker 복구 키 화면이 떠요
부팅 구성 변화를 감지한 정상 동작입니다. Phase 0에서 백업해둔 복구 키를 입력하면 되고, 반복되면 Windows에서 BitLocker를 일시 중지 후 재개(또는 비활성화)하세요.
Linux에서 NTFS 파티션이 읽기 전용으로 마운트돼요
Windows 빠른 시작이 켜져 있거나 최대 절전 상태로 종료된 경우입니다. Windows로 부팅해 빠른 시작을 끄고(Phase 4) 완전 종료 후 다시 시도하세요.
diskpart에서 실수로 다른 디스크를 clean 했어요
새 HDD였다면 데이터 손실이 없으니 그대로 진행하면 됩니다. 만약 데이터가 있던 디스크라면 즉시 사용을 멈추고 복구 도구(TestDisk 등)를 검토 — clean은 파티션 테이블만 지우므로 초기에는 복구 가능성이 높습니다.
