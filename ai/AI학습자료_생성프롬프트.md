# AI 학습자료 생성 프롬프트 (심화판 — ai-engineering-notes용)

> **용도:** AI/음향 ML 주제 1개 → 깊은 학습용 완결 HTML 1개 생성. SWE 프롬프트와 같은 외형(스타일·톤)을 유지하되, 수식·구현·논문 근거를 강제하는 심화 규격.
> **게시 위치:** `ai-engineering-notes/notes/` (파일명 = 주제 제목.html). 목록은 ROADMAP에서 관리.

---

## 호출 템플릿

```
아래 규칙과 골격에 따라 심화 학습자료 HTML 1개를 만들어줘.

- 주제: (예: Mel-spectrogram — 왜, 어떻게 계산되는가)
- 핵심 키워드: (예: STFT/Mel 필터뱅크/로그 압축/파라미터 선택)
- 학습 목표: (이 자료를 읽고 나면 무엇을 할 수 있어야 하는가 1~2줄)
- 파일명: (주제 제목).html
```

---

## 규칙 (온보딩)

**독자 눈높이:** 신호처리 기초(푸리에 변환·필터링·샘플링)는 아는 독자. 단 **최신 딥러닝 도구 체인·아키텍처 구현은 처음**이라고 가정한다. 기초 신호처리의 재설명은 한 줄 환기로 최소화하고, 지면은 **구현·최신 기법·연결**에 배분한다.

### 산출물
- 완결 단일 HTML 1개(주제 1개당). 스타일은 SWE 자료와 동일한 GitHub 라이트 테마·CSS(일관성 유지).
- 언어: 한국어. 영어 병기 3분류 규칙은 SWE 프롬프트와 동일(개념어 최초 1회 병기 / 정착 외래어 한국어만 / 코드 토큰 백틱).
- **수식:** MathJax CDN 1줄 허용(`<script>` 헤더). 모든 수식은 **기호 정의(notation)를 먼저** 제시한 뒤 사용.

### 표준 골격 (이 순서로)
0. **한눈에 보는 결론** (불릿 4~6개)
1. **왜 이 개념인가** — 어떤 문제를 풀려고 등장했는지, 이전 방법의 한계
2~N. **개념 본문 — 수식·직관·구현 삼위일체**: 핵심 개념마다 아래 3종 세트를 **모두** 갖출 것
   - **수식**: 정확한 정의(notation 표 포함)
   - **직관**: 물리적/기하학적 의미 — "이 수식이 실제로 무엇을 하는가"를 말로
   - **구현**: PyTorch(필요 시 NumPy 검증) 코드. **모든 텐서 연산에 shape 주석 필수** (예: `# (B, 1, T) → (B, n_mels, T')`)
★ **고전 신호처리 vs 학습 기반 접근 대조** (시그니처 섹션): 같은 문제를 고전 SP와 딥러닝이 각각 어떻게 푸는지 표로 대조 — 가정·데이터 요구량·해석 가능성·실패 양상. 한쪽만 있는 주제면 "고전적 대응물이 없는/필요 없는 이유"를 서술
- **흔히 헷갈리는 지점** — 개념 자체의 함정(shape 불일치·정규화 누락·프레임/홉 혼동 등). 작은 수치 예시로 검증 가능하게
- **직접 확인하기** — 10~30줄짜리 미니 실험 1개 제안(합성 신호·작은 텐서로 손 검증). 확장 실험은 `projects/` 연계 아이디어로 한 줄
- **한 장 요약** (불릿 4~6개)
- **더 읽기 / 관련 문서** — 논문·문서 링크 + 레포 내 관련 노트

### 근거 규율 (AI 특화 — 중요)
- 핵심 기법·아키텍처는 **원 논문(저자·연도) 앵커 필수**. 이후 발전이 있으면 대표 후속 1~2개까지.
- **최신 여부가 불확실하면 웹서치로 확인 후 서술**(AI는 지식 반감기가 짧다). 확인 못 한 주장에는 "~로 알려져 있다(202X 기준)" 식으로 시점 표기.
- **경향성 서술은 확실해 보여도 웹서치 검증** (2026-07-05 추가): "흔히 헷갈리는 지점" 등에서 쓰는 경향성 주장("~가 보통이다", "~는 안 된다", "~가 주류다")은 기초 주제라도 작성 시점에 웹서치로 현행성 확인 후 필요 시 시점 표기. 구조적 사실(수식·정의·shape)은 면제. (사례: "마스크 예측=생성 불가"는 2025 확산형 LM으로, "RL은 행동만 조형"은 2024~ RLVR로 각각 단서가 필요해짐)
- 논문 그림·표 복제 금지 — 필요하면 직접 재구성한 도식/표로.
- **상호참조는 제목 기반** (2026-07-05 추가): 발행 HTML 안에서 다른 노트를 참조할 때는 노트 번호가 아닌 제목으로. 번호(ID)는 트래킹 문서(AI_trends_track.md) 전용 — 미발행분 순서 변경 시 발행물이 깨지지 않게 하기 위함.

### 내용 원칙
- 결론만 적지 말 것: **왜 이 설계인가, 어떤 대안이 있었고 왜 밀렸는가**(트레이드오프)를 반드시.
- 하이퍼파라미터가 나오면 **"관례값 + 그 관례의 이유 + 언제 벗어나는가"** 3종으로.
- 분량은 SWE보다 길어도 됨. 단 **1문서 = 1개념** 원자화는 유지(길어지면 분할).

### 게시 주의 (공개 리포)
- 범용 지식만. 내부·개인 맥락 서술 금지(SWE와 동일).
- 코드 예제는 실행 가능해야 함(의사코드 금지, 버전 의존 API는 버전 명시).
