## B. 진행 관리 — save-state 이원 체계

9개월+ 장기전. 진척은 프로젝트 검색·메모리만으로는 유실되므로 ".md가 본체" 원리를 이식한다.
**두 개의 save-state 파일을 분리 운영**한다:

| 파일 | 소관 | 등급 |
|---|---|---|
| `progress.md` | 키스톤(1~4단계) 진행 + 전략 메모(커리어·RL·소관·축소 우선순위) | 비공개 |
| `AI_trends_track.md` | 트렌드 복습 트랙(모듈 A/B/C) 진행 | 공개 안전(커리어 메타 금지) |

### 갱신 규칙
- 작업 세션 종료 시마다 각 파일 "현재 위치"와 "갱신 이력"에 한 줄 추가.
- 키스톤 체크박스 완료 시마다 §E 회수 포맷으로 커리어 방 회수 여부 판단.
- progress.md에는 메타 맥락을 자유롭게, AI_trends_track.md에는 기술 서술만(§I).

> progress.md 최소 포맷·체크리스트는 현재 운영 중인 실파일을 정본으로 삼는다(1단계 Block 0~4,
> 도구체인 메모, 전략 메모 포함). 원본 v1의 간이 포맷은 대체됨.

- 새 노트 삽입 시 **발행 범위 뒤에 배치**를 우선(발행물 자기 태그 재번호 최소화). 불가피하면 자기 태그만 패치.

### 참조 안정성 (파일명·식별자)
- 파일명에 버전 접미사(_v2 등) 금지 — 참조가 버전 올릴 때마다 깨진다. 버전은 문서 내부 [변경 이력]로.
- 노트 상호참조는 제목 기반(번호 금지). 이름·번호 같은 가변 식별자를 참조 경로에 넣지 않는 것이 공통 원칙.

### 공개 전 관문
- 푸시 세트 조립 시 전수 검사: `방산·이직·커리어·PhD·박사·소나·표적·전자전·자소서·면접` +
  내부 운영 용어(`키스톤·모듈 A/B/C·Block N`) grep → 노트 본문은 기술 용어로 중립화.

## K. 노트 생성 규격 (참조)

심화 학습자료 HTML 생성은 `AI학습자료_생성프롬프트.md`를 정본 규격으로 따른다. 핵심:
- 표준 골격: 한눈에 보는 결론 → 왜 이 개념인가 → 수식·직관·구현 3종 세트(shape 주석 필수) →
  **★고전 SP vs 학습 기반 대조(시그니처)** → 흔히 헷갈리는 지점 → 직접 확인하기(미니 실험) → 한 장 요약 → 더 읽기.

  **경향성 서술("~가 보통이다", "~는 안 된다")은 확실해 보여도 웹서치 검증**(기초 주제 포함).
