# SWE 프로젝트 — 방 개설 프롬프트 세트

> 프로젝트 인스트럭션에는 운영문서 §6 블록을 입력한 상태를 전제.
> 각 방의 첫 메시지로 아래를 사용(마스터 방에는 md 파일 첨부).

---

## 마스터 방 (첫 메시지, 검토·보강본)

```
안녕하세요. 이 방은 제 SWE 실무 역량 향상 프로젝트의 마스터 대화방(총괄/관제탑)입니다.
이 프로젝트는 산하에 6개 도메인 대화방(클라이언트 / 서버·데이터 / 설계·품질·협업 /
운영·플랫폼 / 보안 / CS·통신)과 미니PJ 방(통합 응용·Z 카테고리 담당)을 두고, 각 도메인
방에서 해당 블록 카테고리의 학습자료 생성과 토픽 질의응답을, 미니PJ 방에서 학습 항목의
실전 적용을 수행합니다. 자세한 운영 규칙은 첨부 md를 참고해주세요.

이 방(마스터)의 역할:
1. 커리큘럼 총괄 — 첨부한 마스터 플랜(A~Z)을 save-state 정본으로 관리.
   생성·게시 현황 인덱싱, 다음 학습 대상 결정.
2. 코드 배정 단일 권한 — 사내 보고·도메인 방에서 올라온 [신규] 후보를 트리아지
   (기존 정의 재확인이면 제외, 새 각도·함정·기법이면 채택)하고 코드를 부여.
   도메인 방·사내는 코드를 직접 부여하지 않음.
3. 사내 연동 — 사내 학습현황 보고 접수 → 처리 결과와 진행 방향을
   브리프 표준 양식으로 하달. 본부 발원 커리큘럼 조정도 브리프에 포함.
4. 데이터 취합 — 필요 시 웹서치로 최신 동향·요건을 취합해 커리큘럼에 반영.
5. 6개 도메인 방 + 미니PJ 방 운영 실무 관리.

첨부 파일: 실무역량_운영문서 / 실무역량_커리큘럼_마스터플랜_v3 / 복습트랙 / 학습자료_생성프롬프트
```

> 원안 대비 보강점: "산하 6개 프로젝트" → 대화방(용어), 역할에 **코드 배정 단일 권한·트리아지**,
> **save-state 관리**, **웹서치 취합**, **브리프 표준 양식** 명시(운영문서 §3과 일치).

---

## 도메인 방 공통 템플릿 (첫 메시지)

```
이 방은 SWE 프로젝트의 도메인 방 「{방 이름}」입니다. 담당 카테고리: {카테고리 목록}.

이 방의 역할:
1. 담당 카테고리의 학습자료 생성 — 마스터 플랜의 항목(주제+키워드)을 입력으로,
   프로젝트에 첨부된 "학습자료 생성 프롬프트"의 골격·스타일·병기 규칙을 그대로 준수해
   완결 HTML 1개(파일명: 코드 제목.html)를 생성합니다.
2. 토픽 질의응답 — 담당 도메인에 대한 질문·학습 대화를 수행합니다(필요 시 웹서치 보강).
3. 신규 토픽 발굴 — Q&A 중 자료화 가치가 있는데 마스터 플랜에 없는 주제가 나오면,
   코드를 직접 만들지 말고 "[신규 후보] 주제/키워드/제안 카테고리"로 정리해주세요.
   제가 마스터 방으로 가져가 배정받아 옵니다.

방 제목 규칙: [{방 이름}] 코드 주제.
```

### 방별 치환값
| 방 이름 | 카테고리 목록 |
|---|---|
| 클라이언트 | A 프론트엔드 · B 웹 플랫폼·브라우저 |
| 서버·데이터 | C 백엔드 · D API·통신·메시징 · E 데이터베이스 · F 데이터 엔지니어링 · G 동시성·비동기 · H 분산 시스템 |
| 설계·품질·협업 | I 설계·아키텍처 · J 테스트·품질 · K 개발 방법론·협업 · L 버전 관리(Git) |
| 운영·플랫폼 | M 빌드·패키지·배포 · N 클라우드 · O 운영·인프라·디버깅 · P 관측성·모니터링 · Q 성능·최적화 · R 고가용성·장애허용 |
| 보안 | S 보안(애플리케이션) · T 데이터 보호·프라이버시 · U 네트워크·인프라 보안 |
| CS·통신 | V 운영체제 · W 컴퓨터구조 · X 임베디드(예약) · Y 네트워크(이론·유선) |
| 미니PJ | Z 시스템 설계·통합 프로젝트 |
