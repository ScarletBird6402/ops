# [마스터 방 전달] 미니PJ 방 — Z 카테고리 담당 개시 (2026-07-17)

## 1. 결정 사항

컨트롤룸·마스터 방 결정으로 **Z 카테고리(시스템 설계·통합 프로젝트)** 가 신설되었고, **이 방이 담당 방**이 된다. 미니PJ 방은 커리큘럼 소비자에서 **카테고리 보유 주체**로 위상이 바뀐다.

- 배경: 카테고리 동결 1회 예외로 구 Z(무선·통신 예약, 항목 0·자료 0·링크 0)를 재용도화. 기존 A~Y 코드는 일절 불변.
- 현재 항목: **Z1 시스템 설계 방법론** / **Z2 URL 단축기**(진행 중인 프로젝트를 소급 편입).

## 2. Z 항목의 산출물 구조 — "설계 문서 + 구현" 한 쌍

각 Z 항목은 두 산출물로 완성된다.

| 산출물 | 위치 | 작성 주체 |
|---|---|---|
| **설계 문서** (`Z코드 제목.html`) | swe-notes `Z 시스템 설계·통합 프로젝트/` 폴더 | **이 방** (Z2~ 프로젝트 문서) |
| **구현** | swe-projects/프로젝트 폴더 | 이 방 (기존과 동일) |

- **예외 — Z1**: 시스템 설계 *방법론* 은 학습자료 성격이므로 **본부 생성 원칙**을 따른다(이 방이 생성하지 않음). Z1이 확정한 골격을 Z2~ 설계 문서가 따른다.
- **Z2~ 설계 문서 골격** (Z1 게시 전까지의 잠정 표준): 요구사항 정리 → 백오브엔벨롭 추정 → 아키텍처 스케치(대안 비교) → 트레이드오프 서술 → 구현 결과와의 대조(회고 시 보강). 학습자료의 언어별 대조 섹션은 **불요**.
- 파일명 규칙 동일: `Z2 URL 단축기.html` (괄호 병기부 제거 규칙 포함). 스타일은 학습자료와 같은 GitHub 라이트 테마 CSS 재사용.

## 3. 운영 규칙 (기존 + 신규)

1. **Z 코드 배정은 마스터 방 단일 권한** — 새 프로젝트 착수 시 이 방에서 직접 Z 번호를 부여하지 않고 마스터 방에 요청한다(기존 [신규 후보] 절차와 동일한 원리).
2. **공개 품질 기준 적용** — Z 설계 문서는 공개 학습노트(swe-notes)에 게시되므로, 미니PJ 회고·설계 서술에도 학습자료와 동일한 기준이 적용된다: 비식별·범용 예제만, 실무 맥락·경험담 명시 금지, 관련 문서 링크는 확정 코드·제목만(임의 파일명 금지, 미확정은 "확정 후 링크 예정").
3. **커버리지 기록 유지** — 각 프로젝트가 적용한 커리큘럼 코드(A~Y) 기록은 기존과 동일. Z 설계 문서의 "구현 결과와의 대조" 절이 이 기록의 서사 버전이 된다.
4. 회고 발 신규 학습 주제는 기존대로 `[신규 후보] 주제/키워드/제안 카테고리` 형식으로 마스터 방 보고.

## 4. 즉시 액션 — Z2 URL 단축기

1. 진행 중인 URL 단축기는 **Z2로 소급 편입**됨 — 이후 산출물·보고에서 `Z2` 코드 사용.
2. 구현 완료 시 회고와 함께 **`Z2 URL 단축기.html` 설계 문서 초안**을 작성해 마스터 방으로 제출(§2 잠정 골격). 검수 후 swe-notes 게시.
3. 확정 적용 코드(D2·E1·C10·I1·P1·S3·C18, C17은 회고 판정 대기)는 설계 문서의 대조 절과 커버리지 로그 양쪽에 기록.
4. 관련 학습자료가 전부 게시 완료 상태다(D2·E1·C10·I1·P1·S3·C17·C18) — 구현 중 막히면 해당 문서 참조.

## 5. 다음 프로젝트부터의 흐름 (요약)

```
소재 발굴(이 방) → Z 코드 배정 요청(마스터 방) → 기획·구현(이 방)
→ 회고 + 설계 문서 작성(이 방) → 마스터 방 검수 → swe-notes 게시 + 커버리지 로그 갱신
```
