## 주간 전송 블록 생성

사용자가 **"주간 블록"** 또는 **"이번 주 전송용 정리"** 를 요청하면, 그 주의 일일 보고들을 집계해 아래 형식으로 출력한다. 이 블록은 본부로 수기 전달되므로 **최소 텍스트**가 목표다.

```
[W## 주간 · MM/DD~MM/DD]
접촉: K5×3 K2×2 I17 I32 A15 E20
신사례(선택): I16 시간 퇴화 시그니처 / K9 두 원인 동일 증상
신규:
 · 주제 / 키워드 3~5 / 카테고리 / 인접 코드 1개
 · 주제 / 키워드 3~5 / 카테고리 / 인접 코드 1개
AI소관:
 · 주제 / 키워드 3~5  (에이전트·LLM 특성이 본체인 것 — 아래 규칙 6)
판단요청: (있을 때만 한 줄)
```

### 규칙
1. **접촉 = 코드 + 횟수만.** 설명·사례 문장은 쓰지 않는다. 같은 코드가 서로 다른 작업에서 등장한 횟수를 `×N`으로 병기(같은 작업 흐름 안의 반복은 1회). 코드는 본부 코드(마스터플랜 v3)로 — 사내 자체 넘버링만 있는 경우 **제목 병기**(예: `K9 문제 해결 방법론`).
2. **신사례 = 선택, 한 줄, 최대 3건.** 기준: 기존 항목의 **구조를 바꿀 만한** 새 각도일 때만(예: "시그니처가 처음부터 거짓이 아니라 시간이 지나며 퇴화한다"). 단순 재확인·동일 유형 반복은 접촉 횟수에 이미 반영되므로 쓰지 않는다.
3. **신규 = 3요소 한 줄.** 주제 / 키워드 3~5개 / 제안 카테고리 / 가장 가까운 기존 코드 1개. 분업 논거·발굴 경위는 쓰지 않는다 — 인접 코드 하나로 본부가 판정한다. 인접 코드를 모르면 `인접: 없음`.
4. **판단요청**은 카테고리 귀속이 모호하거나 병합 여부가 갈릴 때만 한 줄.
5. 블록 외 부가 설명은 붙이지 않는다. 블록이 15줄을 넘으면 신사례부터 줄인다.
6. **`AI소관:` 분기 (에이전트 업무 발원분)** — 판정 기준 하나: **"에이전트/LLM을 빼도 성립하는 원리인가?"**
   - 성립하면 → `신규:` 또는 `접촉:`(SWE 커리큘럼). 예: 툴 호출 스키마 검증(입력 경계 일반), 툴 호출 재시도·멱등, 에이전트 상태 머신·비동기 오케스트레이션·관측성·인가.
   - LLM 특성이 본체면 → `AI소관:`(AI 프로젝트로 전달). 예: 프롬프트 설계, RAG 청킹·검색 전략, 모델 선택·평가, 컨텍스트 윈도 관리.
   - 애매하면 `판단요청:`에 한 줄 — SWE 본부가 판정 후 이관 회신.
   - **AI 코드 체계 = `AI-` 접두**(컨트롤룸 확정 09-02). AI 커리큘럼 코드는 항상 `AI-A3` 형태로 병기 — 접두 없는 코드는 전부 SWE 커리큘럼. `AI소관:` 항목에 기존 AI 코드가 있으면 `AI-` 포함 표기, 없으면 주제만.

### 예시 (변환 전 → 후)
변환 전 (일일 보고 접촉 항목):
> K5 조용한 실패 — import 누락 예외가 디바운스 콜백에 삼켜져 콘솔에만 잔류
> K2 grep 영향범위 — 프론트 방어 추가 전 백엔드 기존 검사 재확인
> K3 컨벤션 조사 — 해당 파일 기존 습관이 팀 관례 아닌 개인 습관임을 빈도 조사로 판별

변환 후 (주간 블록의 접촉 줄):
> 접촉: K5 K2 K3

— 세 설명 중 "개인 습관 vs 팀 관례 판별"만 K3 구조를 바꿀 각도라면 신사례 한 줄로: `신사례: K3 개인 습관 vs 팀 관례 판별`
