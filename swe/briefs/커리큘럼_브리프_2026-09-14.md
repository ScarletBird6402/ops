## 4. 규칙 확정 (이 기간 판정에서 공식화)
1. **채택 vs 흡수 기준**: 기존 항목 원리의 **적용 사례**면 흡수, **신규 원리가 본체**면 채택. 인접 항목의 대칭축·세트는 병합 채택 가능(한 문서 두 방향).
2. **흡수처 판단**: 최근 채택 항목보다 **원리를 정의한 항목**을 우선 지목(예: 부결 보존은 K4가 아닌 K16, 3값→2값 손실은 K20이 아닌 I24).
3. **S 귀속 기준 재확인**: 공격 모델이 있어야 의미가 생기는 통제 → S. 공격 없어도 성립하는 설계 원리 → 해당 도메인(I34 불변식 시행 위치가 I인 이유).
4. **작업 방식 중립화**: 특수 작업 방식(도구·협업 구조)에서 발원한 보고도 **일반 개발 워크플로우 관점으로 정의**된다(K18·K22 적용). 보고 시 특수 어휘를 미리 일반화할 필요는 없음 — 본부에서 처리.
5. 사내 자체 넘버링(예: H9)은 제목 병기로 자동 해석됨 — 계속 병기.
7. **프로젝트 간 경계(09-02 컨트롤룸 확정)**: 에이전트·LLM 업무 발원 보고는 **"LLM을 빼도 성립하는 원리인가?"** 로 분기 — 성립하면 SWE(이 커리큘럼), LLM 특성이 본체면 AI 프로젝트(코드 `AI-` 접두). 상세·예시는 패치 확정판 규칙 6.
6. **보고 전송 포맷 압축(신규)**: 본부 전송용 주간 블록을 아래 형식으로 — 접촉은 **코드+횟수만**(설명 생략), 신사례는 생성 재료로 가치 있을 때만 한 줄, 신규는 **주제/키워드 3~5/카테고리/인접 코드 1개**. 판정에 필요한 정보는 이것으로 충분하며, 일일 보고는 사내 기록용으로 기존 형식 유지 가능.
