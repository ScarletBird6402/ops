# 실무 역량 프로젝트 — 운영 문서

> **※ 본부 전용 — 사내 반입 금지.** 이 문서에는 반입 불가 정보가 포함된다. 사내 반입 세트는 브리프 + 마스터플랜 2종뿐(§2 브리프 양식 참조).

> **성격:** 업무 인사이트 발원의 개발 실무 지식을 학습자료(HTML)로 재생성·누적하고 GitHub에 게시하는 프로젝트의 운영 규칙.
> **동반 파일:** `실무역량_마스터목차.md`(살아있는 인덱스/save-state), `학습자료_생성프롬프트.md`(자료 생성 프롬프트).

---

## 0. 목적 · 성격

- 업무 인사이트에서 발원한 **개발 실무 지식 + CS 이론**을 학습자료로 재생성·누적.
- 학습 발원은 3갈래: ① **사내 발원**(현장 보고) ② **본부 발원**(도메인 방 질의응답) ③ **복습 트랙**(원자화 전 학습분). 우선순위 ①>②>③.
- 산출물(HTML)을 **GitHub에 게시** → (a) 영구 참고 지식베이스, (b) 포트폴리오.
- CS 이론을 이 프로젝트로 **통합 운영**(별도 CS 프로젝트 없음). 단 자료구조·알고리즘·프로그래밍 언어는 알고리즘 프로젝트 소관(경계는 §4).

## 1. 두 환경 격리 + 단일 브릿지 (전제)

Bedrock 도입으로 생긴 건 **구조적 경계**다.

| | 사내 (Bedrock Claude) | 개인 (claude.ai) |
|---|---|---|
| 역할 | 실무 중 실시간 인사이트 획득 | 학습자료 생성·보관·복습 |
| 연결 | **없음 — 메모리·프로젝트·검색 전부 단절** | 좌동 |
| 반출 | 파일·내부 콘텐츠 불가 | — |

두 Claude는 완전히 다른 우주다. 잇는 유일한 다리 = **손으로 나르는 범용·비식별화 텍스트(목차 엔트리)** 하나뿐.

## 2. 크로스환경 워크플로우

```
[사내 Bedrock]  →  [손으로 나르는 목차 엔트리]  →  [개인 claude.ai]
 인사이트 획득       범용화·비식별화 텍스트            HTML 자료 재생성 + 게시 + 학습
```

**사내에서 (자료 생성 아님, "포획"만):**
```
[학습목차 엔트리]
- 코드: (A~Z + 번호, 예: I4)
- 주제: (범용 개념명)
- 핵심 키워드: (props/emit/... 형태)
- 맥락: 범용만 — "Vue3 프론트/Java 백엔드 웹개발 입문자".
        내부 시스템명·사내 코드·파일명 절대 금지.
- (선택) 인사이트 트리거 한 줄: 무엇을 하다 왜 필요했나(일반화)
```
규율 = **포획 시점에 일반화 + 비식별화.** 특정 업무 상황을 범용 CS 개념으로 변환해서만 기록.

### 코드 체계 이원 운영 (본부 ↔ 사내)
- **본부(개인/공개 리포)** = 동결 A~Z 체계(마스터 플랜 v2)가 유일 정본.
- **사내 리포** = 기존 자료가 대량 축적되어 있어 **자체 코드 매핑을 별도 유지**(교체 비용·내부 링크 안정성 때문). 본부는 사내 내부 매핑을 관리하지 않는다.
- **브릿지 규칙**: 사내 → 본부 보고([학습목차 엔트리])는 **사내가 본부 코드 기준으로 변환해 작성**한다. 즉 마스터 방에 도착하는 모든 코드는 본부 코드로 간주. 본부 → 사내 브리프도 본부 코드로 발신하며, 사내 코드로의 역변환은 사내가 수행.
- **보고 엔트리는 코드+제목(주제명) 병기 권장**: 코드는 체계를 타지만 제목은 타지 않으므로, 변환 누락·매핑 오류 시 본부가 제목으로 자동 복구할 수 있다.
- **사내→본부 카테고리 매핑 확인분(누적)**: B→C · F→I · G→J · H→K · K→O. 미확인 사내 코드가 보고에 나타나면 임의 해석하지 않고 회신 요청.
- **정본 동기화 규칙(Phase 1, 첨부 배포 체제 한시)**: 브리프 발행 시점 = 프로젝트 첨부 갱신 시점. 사내 반입본과 프로젝트 첨부를 같은 최신 마스터플랜으로 동시 교체한다. 도메인 방은 첨부 배포일 이후 배정 코드에 대해 마스터 방 회신을 정본으로 간주.
- **계획(마스터 플랜)에 없는 주제**: 사내가 임의로 코드를 매핑하지 않고 **[신규]로 보고**한다. 편입 여부·코드 배정은 **본부 판단**(단일 권한) — 코드 규칙 일관성 유지.

**개인 환경에서 (재생성 + 게시):**
1. 목차 엔트리를 `학습자료_생성프롬프트.md`에 넣어 완결 HTML 1개 생성.
2. GitHub 리포 커밋 → Pages 렌더.
3. `실무역량_마스터목차.md`의 생성·게시 상태 갱신.

### 자료 생성 일원화와 사내 파생본 (2026-07-13 확정)
- **자료 생성은 본부 전용**: 학습자료 HTML은 본부(Fable 표준)에서만 생성. 사내는 생성하지 않는다(토큰 절약 + 생성 경로 단일화로 공개 리포 유출 벡터 제거).
- **사내 파생본 = 부가 편집만**: 반입한 원본에 `## 실무 연결` 섹션 1개를 "관련 문서" 직전에 **추가만** 한다(첫 줄에 `원본 기준: YYYY-MM-DD` 표기, 기존 CSS 재사용). 본문·골격·링크·범용 예시는 무수정. 공개판에는 이 섹션이 존재하지 않는다.
- **단방향 파생**: 본부 정본(범용) → 사내 파생본(업무 사례). 파생본·실무 사례는 어떤 형태로도 사외 반출 금지. 파생 과정에서 나온 개선점은 기존 규율대로 범용화·비식별화된 목차 엔트리로만 보고.
- **본부 개정 시**: 새 원본 재반입 + 구 파생본의 실무 연결 섹션만 복사-이식.

### 생성 캐던스 운용 — 2단계 모델 (2026-07-13 확정)
- **학습·자료화 분리 원칙**: 주제 노출 시점의 학습은 업무 자체 + 도메인 방 Q&A에서 즉시 수행. 자료화(HTML)는 비동기 큐 — 자료 부재는 학습의 전제 조건이 아니다.
- **재접촉 가중 정렬**: 업무 접촉 로그의 코드 등장 횟수가 곧 빈도 집계. 주간 리뷰에서 "등장 횟수 상위 × 미게시"를 뽑아 생성 큐로 삼는다. **사내의 별도 빈도 순위 보고는 폐지**(접촉 코드+제목만 기록하면 본부 로그가 집계).
- **[긴급] 레인**: 즉시 필요 주제는 사내 보고 엔트리에 `[긴급]` 태그 → 본부 큐 최상단 → 익일 반입 목표. 상한 주 2~3건(초과분은 일반 큐).
- **Phase 1 (스톡 소진기, 현재)**: 접촉-미게시 스톡을 재접촉 가중 순으로 소진. 병목은 과도기 스톡 문제로 간주.
- **Phase 2 (포화기)**: 생성 여력이 유입을 추월하면 복습 트랙 잔여 → CS 베이스(V·W·Y) → 예약 카테고리(X·Z) 개시 순으로 전환.
- **전환 지표**: 주간 접촉 중 신규 코드 비율이 **2주 연속 10% 미만**이면 Phase 2 선언(접촉 로그에서 자동 산출).

### 복습 트랙 (원자화 전 학습분 재생성)
- 처음 목차(원자화 전)는 지금까지 **실무에서 이미 다룬** 주제들이다. 이를 최종 코드로 매핑한 목록이 `복습트랙_원자화전_재생성목록.md`(총 80개).
- 이 항목들은 **복습 차원에서 틈틈이 한두 개씩 재생성**해 공부한다. 신규 실무 발원 항목이 항상 우선이고, 복습 트랙은 여력이 있을 때 소진한다.
- 재생성 시 "확장/분리된 항목"은 넓어진 범위·새 관점을 반영해 다시 만든다(단순 재현 아님).

### 본부 발원 루프 (도메인 방 질의응답 → 자료화)
- 도메인 방은 자료 생성소만이 아니라 **토픽 질의응답 공간**이다. 궁금한 주제를 그 방에서 묻고 학습한다(필요 시 웹서치로 최신 정보 보강).
- 질의응답에서 **자료화 가치가 있는 주제**가 나오면:
  1. 기존 코드에 해당 → 그 코드로 자료 생성(또는 기존 자료의 사례 보강).
  2. 기존에 없음 → **마스터 방에 [신규] 편입 요청**(주제+키워드+제안 카테고리). 코드 배정은 마스터 방만 한다.
- **트리아지 기준(사내 보고와 동일)**: 기존 코드 정의를 문자 그대로 재확인만 하는 지엽 주제는 편입하지 않는다. 새 각도·새 함정·새 기법을 더할 때만 채택.
- 본부 발원으로 커리큘럼이 조정되면, 다음 **브리프에 조정 내역을 담아 사내로 전달**한다(사내가 같은 코드 체계를 유지하도록).

### 브리프 표준 양식 (본부 → 사내, 반복 사용)
```
[커리큘럼 브리프] YYYY-MM-DD
1. 코드 배정 결과: (사내 보고의 [신규] 처리 — 배정 코드 + 한 줄 근거)
2. 본부 발원 조정: (본부 Q&A로 추가·변경된 항목 — 있을 때만)
3. 마스터 플랜 교체 여부: (교체 시 최신 마스터플랜 별첨 / 없으면 "변경 없음")
4. 기타 운영 변경: (있을 때만)
```

**반입 판본 정책(2026-07-17 확정 — 2층 체계):**
- 사내 반입 세트 = **브리프 + 마스터플랜, 딱 2종**. 운영문서·복습트랙·기타 본부 문서는 반입 금지.
- 마스터플랜은 별도 클린 판본 없이 **본부 정본을 그대로 반입** → 따라서 플랜에는 반입 가능한 커리큘럼 정보만 기재(운영·전략성 정보는 이 운영문서로). 클린 판본 체계는 폐기.
- **발행 전 민감어 스캔 필수**(브리프·플랜 2종 모두): `이직|커리어|방산|KAI|한화|\bLIG\b|면접|자소서|승진|JD` — 게시-검증 에이전트 또는 PowerShell Select-String. 0건 확인 후 반입.

## 3. 프로젝트 구조

프로젝트 하나(**실무 역량**) 안에 방(대화):

- **마스터 방 = 총괄(관제탑)**. 본 방. 역할:
  - `실무역량_커리큘럼_마스터플랜_v3.md`(동결본)를 **save-state로 관리**(신규 append·생성/게시 인덱싱·다음 학습 대상 결정).
  - **코드 배정 단일 권한**: 사내 보고·도메인 방 편입 요청의 [신규]를 트리아지하고 코드 부여.
  - **데이터 취합**: 필요 시 웹서치로 최신 동향을 취합해 커리큘럼에 반영.
  - **사내 브리프 발신**: 배정 결과·본부 발원 조정 내역을 브리프 표준 양식(§2)으로 정리.
- **도메인 방(6개) = 현업(방=블록)**: 클라이언트 / 서버·데이터 / 설계·품질·협업 / 운영·플랫폼 / 보안 / CS·통신. 역할:
  - 담당 카테고리의 **자료 생성 + 학습**.
  - **토픽 질의응답**: 해당 도메인 질문·학습 대화 수행(웹서치 보강 포함).
  - Q&A에서 신규 토픽 발굴 시 **마스터 방으로 편입 요청**(직접 코드 부여 금지).
- **미니 프로젝트 방(1개) = 통합 응용**: 학습한 커리큘럼 항목(A~Z)을 작은 실전 프로젝트로 적용. 기획(적용 코드·완료 정의)→구현→회고 흐름, 적용 코드를 마스터 플랜의 미니 프로젝트 로그에 기록. 회고 발 신규 주제는 [신규 후보]로 마스터 방 보고(코드 부여 금지). 산출물은 `swe-projects` 단일 공개 레포에 프로젝트별 폴더로 저장(2026-07-06 확정, 규모 초과 시 개별 레포로 졸업). 공개 품질 기준은 학습노트 리포와 동일. 제목: `[미니PJ] 프로젝트명`.

**카테고리 → 방 매핑** (방 = 블록, 마스터 플랜 A~Z)
| 방(블록) | 카테고리 |
|---|---|
| 클라이언트 | A 프론트엔드 · B 웹 플랫폼·브라우저 |
| 서버·데이터 | C 백엔드 · D API·통신·메시징 · E 데이터베이스 · F 데이터 엔지니어링 · G 동시성 · H 분산 시스템 |
| 설계·품질·협업 | I 설계 · J 테스트 · K 방법론 · L Git |
| 운영·플랫폼 | M 빌드·배포 · N 클라우드 · O 운영·디버깅 · P 관측성 · Q 성능 · R 고가용성(HA/FT) |
| 보안 | S 보안(앱) · T 데이터 보호 · U 네트워크·인프라 보안 |
| CS·통신 | V 운영체제 · W 컴퓨터구조 · X 임베디드(예약) · Y 네트워크(유선) |
| (예외) 미니PJ | Z 시스템 설계·통합 프로젝트 — 설계 문서=swe-notes, 구현=swe-projects |

> 프로젝트 내 검색은 방을 가로지르므로 배치는 정리용. 교차 개념은 어디 있든 검색된다.
> 제목 규칙: `[카테고리] 코드 주제`(예: `[설계] I4 의존성 주입`).

## 4. 경계 · 마스터 플랜 안정성

### 알고리즘 프로젝트와의 경계 (CS는 이 프로젝트로 통합됨)
| 분류 | 소속 |
|---|---|
| 개발 실무 + CS 이론(OS·구조·네트워크 이론) | **이 프로젝트**(A~Z) |
| 자료구조 · 알고리즘 · 프로그래밍 언어 · 구현 | **알고리즘 프로젝트**(별도, 개설 보류) |
| AI·LLM 활용 개발(프롬프트·RAG·에이전트·LLM 통합) | **AI 프로젝트**(별도) |

> 알고리즘 프로젝트는 AI 코딩 확산으로 우선순위 낮음 → 여유·시험 준비 시 개설. 겹치면 cross-link만.

### 마스터 플랜 안정성 규칙 (동결 장치)
- **안정층(불변)**: 카테고리 집합 + 알파벳 코드. 이번 v2로 **동결**, 이후 변경 없음.
- **코드 확장 규칙(A~Z 소진 이후)**: 신규 카테고리·블록이 불가피하면 엑셀 열 번호 방식으로 **AA, AB, … 2문자 코드**를 부여. 단, 기존 코드 시프트 금지 — 블록 논리 배치와 무관하게 **말미 append만** 허용(파일명·링크 안정성 유지). 배정 권한은 기존과 동일하게 마스터 방 단일.
- **성장층(증가)**: 항목은 해당 카테고리의 **다음 번호로 append만**.
- **코드 회수·재사용 금지**: 항목을 폐기해도 번호는 비워둠(뒤 번호 당겨오지 않음). ← 파일명·GitHub 링크 안정성의 핵심.
- 신설 카테고리도 골격에 전부 편입하되, 자료 생성은 **업무 유입 시 또는 유입량 감소 시** 착수.
- **예약 코드(X 임베디드·Z 무선·통신) — 커리어 연계 트리거(본부 전용 정보)**: 두 카테고리는 업무 발원이 불가능하지만 **커리어(방산) 대비로 개시가 필요가 확정된 영역**이다. 콘텐츠는 3층으로 분리 운영:
  - **방산 특화**(소나·전자전·무기체계 등) → 커리어 방 + ops/career 소관. **공개 절대 금지**, 이 커리큘럼 밖.
  - **무선·통신 일반이론** → 주 학습은 **AI 프로젝트**(신호처리 확장 트랙, ROADMAP 4단계). 무선 *네트워킹* 주제는 Y 항목으로 append. (**Z는 2026-07-16 재용도화** — 시스템 설계·통합 프로젝트, 미니PJ 소관. 동결 예외 1회, 마스터플랜 changelog 참조)
  - **임베디드 일반이론**(RTOS·인터럽트·펌웨어) → **X 개시 대상**. 공개 서사 = V·W(OS·구조)의 저수준 연장.
  - **개시 트리거 = 커리어 방의 "이직 준비기 진입" 판단** → status/career.md 전달사항으로 SWE(X)·AI(통신 트랙)에 신호 → 마스터 방이 X1~ 코드 배정. 공개본(CURRICULUM·index)의 "개시 여부 미정" 중립 문구는 **그대로 유지**(변경 시 오히려 낌새).

## 5. GitHub · 포트폴리오 운영

- 리포 = 생성 HTML을 **GitHub Pages 학습노트 사이트**로 게시 → 브라우징 가능 + 포트폴리오.
- 사이트 구조 = A~Z 카테고리 + `index.html`(마스터 플랜이 사이트 인덱스 역할).
- **파일명 = `코드 제목.html` 단일 규칙**(예: `I4 의존성 주입과 테스트 용이성.html`). 제목의 **괄호 병기부는 파일명·상호링크에서 제거**(예: 정본 "분산 추적(tracing)" → `P4 분산 추적.html`). 포트폴리오·개인 학습 겸용 단일 레포. 코드 동결이 곧 링크 안정성. 레포에 학습 계획표(CURRICULUM.md, 클린 버전) 첨부.
- **공개 리포이므로 비식별화 이중 필수**(내부 콘텐츠 금지). 범용 지식만 담기에 공개 안전.
- 포트폴리오 시너지: AI 프로젝트 SELD 리포(기술 깊이) ↔ 이 학습노트 사이트(폭·문서화 역량).

[채팅 운영 규칙]
- 마스터 방 = 총괄: 마스터 플랜 save-state 관리, [신규] 트리아지·코드 배정(단일 권한),
  웹서치 기반 데이터 취합, 사내 브리프 발신.

  Q&A에서 신규 토픽 발굴 시 마스터 방으로 편입 요청(도메인 방의 직접 코드 부여 금지).
